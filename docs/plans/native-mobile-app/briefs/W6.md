## M8-T2a: EAS native-binary strategy for forme-native (Codex, pulled forward). Branch `mobile/M8-T2a`

Runs during M1 because it touches only `packages/forme-native` and new CI files. M8-T2 then only wires the result into `eas.json`.

**Target:** EAS Build (Linux Android workers and macOS iOS workers without Rust) can build the app with `@reactive-resume/forme-native` without running Cargo, and local dev keeps `bash rust/build.sh`.

**Change:**

- Pick and implement one strategy, recording the trade-offs in the report: (a) a GitHub Actions workflow builds the xcframework and jniLibs on macOS for each `forme-native` version and publishes them as a release asset (or workflow artifact) keyed by a content hash of `rust/**`; an Expo config plugin or `postinstall`/`eas-build-pre-install` hook fetches and verifies (SHA-256) them before prebuild; or (b) EAS build hooks that install Rust and run `rust/build.sh` on the worker (slower; Linux workers cannot build the iOS xcframework, so this only works if Android cross-compiles on Linux). Prefer (a) unless it is clearly worse.
- A prebuilt fetch must verify a pinned checksum, must never run on web/server installs, and must fall back to a clear error that says how to build locally.
- Keep the binaries gitignored. Do not add npm dependencies; use Node built-ins (`fetch`, `crypto`) in scripts.
- `packages/forme-native/README.md`: document the flow.
- Third-party notices: generate `packages/forme-native/THIRD_PARTY_NOTICES.md` from the crate graph (HarfBuzz Old-MIT and every Rust crate licence) with a script (`cargo about` or `cargo license` only if already installed; otherwise a small script reading `cargo metadata`). M8 shows it in the app's licences screen.

**Ownership:** `packages/forme-native/**` except `package.json` (ask if you need a script entry; the coordinator adds it), `.github/workflows/mobile-forme-native.yml` (new), `docs/plans/native-mobile-app/reports/M8-T2a*`.

**Acceptance:** `pnpm --filter @reactive-resume/forme-native typecheck`, scoped oxlint/oxfmt, `turbo boundaries`; the workflow passes `actionlint` if installed; a local dry run of the fetch script against a locally built artifact (file URL or local server) with checksum verification.
