## Target

A throwaway Expo app (latest stable SDK) in `apps/spike-s3/` that does the following against a locally running Reactive Resume server:

1. Discovers the auth server through `/.well-known/oauth-authorization-server`.
2. Registers a public native client by DCR.
3. Signs in through the system browser with PKCE (`expo-auth-session` / `expo-web-browser`).
4. Stores the tokens in `expo-secure-store`.
5. Calls `resume.list` and `resume.getById` through `@orpc/client` `RPCLink` against `/api/rpc` with `Authorization: Bearer`, using `fetch` from `expo/fetch`.
6. Consumes one SSE procedure, `resume.updates.subscribe`, through `streamClient`, and receives an event when the resume is edited from the web app.
7. Refreshes the access token with the refresh token.

## Change and questions to answer

1. **Callback.** The target design is an https callback, `https://<server>/auth/native-callback`, intercepted by Universal Links and App Links.
   - Locally, that needs an https tunnel plus AASA/assetlinks. Try `cloudflared` or `ngrok` if installed. Do not sign up for anything; if no tunnel tool is present, skip this part.
   - If the https interception can't be proven locally, prove the rest of the flow with a loopback redirect (`http://127.0.0.1:<port>`; the policy allows it) or with `FLAG_ALLOW_UNSAFE_OAUTH_REDIRECT_URI=true` on your **local** server only.
   - Report exactly what is still unproven about https callbacks, and which iOS API is needed: `ASWebAuthenticationSession` `.https(host:path:)` on iOS 17.4+. Check whether `expo-web-browser` supports it or a small native shim is needed.
2. **SV4: the session lifetime question.** Tokens issued through the browser carry `sid` (the browser session).
   - Show what happens to the access token and the refresh token when that browser session is signed out, or when it expires. Shorten the session expiry locally to test this.
   - State whether a phone stays signed in for weeks without re-auth.
   - Propose the minimal server change if it does not. Do not implement it.
3. **SV5 check.** Confirm that `/api/auth/*` account endpoints (updateUser, apiKey.list) reject the bearer token, and that oRPC `auth.createApiKey`, `auth.exportData` and `auth.deleteAccount` accept it.
4. **Cookie-free password flow.** Note how `resume.verifyPassword` behaves for a bearer client, given that it sets a cookie.
