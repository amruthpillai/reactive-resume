## Delivered

- **Transport** (`src/features/assistant/transport.ts`, `chat.ts`): a port of web `chat.ts`. `useAssistantChat` runs `@ai-sdk/react` `useChat` over a custom `ChatTransport`:
  - `sendMessages` sends only the newest message to `streamClient.agent.messages.send`. It sends the context chips as they are at send time (a ref, not a closure) and the attachment IDs from `body`.
  - `reconnectToStream` uses `streamClient.agent.messages.resume`.
  - SSE strings are parsed with `parseJsonEventStream` and `uiMessageChunkSchema`. A malformed frame is dropped, and only its error name is logged.
  - `sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls`, so answering a question continues the reply.
  - **Difference from web: `resumeStreamIsReplay: true`.** The server's resumable stream replays the reply from its start. Without the flag, resuming after a disconnect duplicated the text already received ("MostMost of your bullets"). The scenario harness caught this.
- **Resume / stop.**
  - Reopening a conversation with `activeRunId` resumes it, as on web.
  - On mobile, an `AppState` return to the foreground also resumes. If the stream errored (the OS cut the connection) and `threads.get` still reports an active run, the chat clears the error and resumes.
  - Stop calls `agent.messages.stop`, then `chat.stop()`, which aborts the request. The partial reply stays, followed by "Stopped. No edits were proposed. Continue".
  - Retry re-sends a failed continuation and regenerates anything else (web parity).
- **`ChatView`** (`src/features/assistant/chat-view.tsx`, the wave contract below). Ports web `Conversation` and `CoachThread`:
  - Lazy thread creation on the first message or the first attachment. An attachment-created draft thread is reused.
  - The thread is re-read when it opens. A brand-new thread skips the read.
  - Message log with auto-follow unless the user scrolled up, "Thinking…", the error card (Retry / Switch model), Copy transcript (`expo-clipboard`).
  - Composer: context chips, attachments, a box that grows to 6 lines, a 34 pt Send/Stop circle in a 44 pt target, and the privacy line. It sits in a `react-native-keyboard-controller` `KeyboardAvoidingView`.
- **Message parts** (`messages.tsx`):

1. **Replay kept earlier parts.**

6. **Attachments.**
   - Sizes are checked before any file is read: at most 10 files, 25 MB each, and 100 MB in all (the server's per-file and per-thread limits).

## Second review fix round: Codex `cce125a4`

FIXED 6.

1. **Recovery continues after an idle timeout.**
   - `recovery.ts` `recoverRun` reloads the thread, shows the saved messages and resumes while the server reports `activeRunId`.
   - When a resumed stream ends early (quiet for 45 s, or cut off), it reloads and resumes again, with backoff (1 s doubling to 30 s).
   - It stops when the server says the run finished (the saved copy is shown) or when the caller moves on.
   - It covers both the reply still running when a conversation opens (`useChat` no longer auto-resumes) and the return to the foreground.
2. **Exact pre-run boundary.** `partsBeforeRun` keeps everything up to the first `step-start` after the last answered question. That includes text or tool results the earlier run wrote after the question in the same step. With no step of the current run yet, the whole message counts as pre-run. This holds for the SDK's message and for the server's saved draft, because both start every step with `step-start`.
3. **Lifecycle generation.**
   - Every follow-up runs under a generation token. Unmount, going to the background, Stop, Send and Retry each start a new generation.
   - `recoverRun` checks its token after every await, before applying messages or resuming.
   - Going to the background ends a running follow-up as well as a live stream.
4. **The Assistant only subscribes to the draft.**
   - `useOpenResumeDraft` opens `resumeId` once, when it mounts, and only if nothing is open in the store (no owner, as after a direct link). It never reopens when another pane changes the draft, and never reclaims it.
   - If a different resume is open, it says so and offers Open resume (the builder route, whose layout owns the draft after the M2-T2 fix).
5. **Strict `?thread=` validation.** A linked conversation stays "pending" (spinner) until the list confirms it, and "failed" (Retry) when the list request fails. Only a positive match about this resume shows the chat and Accept controls.
6. **Page keeps the real draft.**
