## Decisions

- **Reanimated for motion, token durations, default curve.** `tokens.motion.ease*` are React Native `Easing` functions, which are not worklets, so Reanimated cannot use them. Animations take their durations from the tokens and Reanimated's default curve. Reanimated and gorhom already honour Reduce Motion (`ReduceMotion.System`); where tokens.md asks for a cross-fade instead of a slide, the primitive picks it from `useReducedMotion()`. Follow-up below.
- **Shared values are written with `.set()`**: the React Compiler lint (`react(immutability)`) rejects `.value =`.
- **Switch is custom**, not the RN `Switch`, so Android matches Material 3 in the mockups and both platforms honour tokens.
- **Tablet breakpoint** is local to `src/ui` (`useIsWide`, short side ≥ 540) because M2-T2's `useIsTablet()` is not merged. If M2-T2 picks a different rule, `useIsWide` can delegate to it.
- **Raw numbers left on purpose:** platform control sizes from tokens.md §7 (switch 51×31 / 52×32, alert widths 290/320 from the mockups) and derived ones (avatar initials 0.37 × diameter, shimmer ≈ 4 × `d3`). Everything else derives from `space`, `size`, `radius`, `type`, `colors`, `shadows`, `motion`.

## Bugs found and fixed on device

- **Sheets opened on a freshly mounted screen never appeared.** M1's `Sheet` called `dismiss()` on mount while closed; gorhom then ignores the later `present()`. Now only an open → closed change dismisses.
- **A late `onDismiss` could close the next sheet.** `onClose` now fires only for user-started dismissals (swipe, backdrop, Escape), not for `open={false}` from the parent. Review fix: the sheet tracks its dismissal lifecycle (see below).
- **At the largest accessibility text size the stacked iOS dialog buttons overlapped**; fixed, and the dialog body now scrolls.
- **Dark skeleton shimmer smeared black** (`transparent` stops); it now uses `sunken` edges.

## Review fixes (Codex `9f430246`, 5 blockers)

Merged `mobile/native-app` first (`884b26769`, clean; M3-T2, M3-T3, M5-T1, M6-T4 and M7-T1 consume `src/ui`).

1. **Content-sized sheets could not scroll.** Every bottom sheet now uses `BottomSheetScrollView`. Content-sized sheets keep gorhom dynamic sizing with `maxDynamicContentSize` at 90% of the window height, so long content stops there and scrolls; callers need no fractional detents. My earlier finding that content-sized scroll views never present was really the dismiss-on-mount bug, fixed before. Device check: a 30-row content sheet stops at 90% and scrolls to its last row (`ios-overlay-long-light.png`, `ios-overlay-long-scrolled-light.png`); short sheets and the footer sheet still fit their content.
2. **Stale `onDismiss` after close-then-reopen.** The sheet tracks its dismissal lifecycle (`presented`, `closing`). A reopen during a parent-started dismissal waits for that dismissal's `onDismiss`, which presents again and never reports `onClose`. Gallery `open=reopen` closes and reopens 100 ms apart; the sheet stays open (`ios-overlay-reopen-light.png`).
3. **Toast timers leaked.** Timers sit in a map keyed by toast id; `dismissToast`, a replacing `showToast` and `Toaster` unmount clear them.
4. **`SortableItemInfo` fields were required.** `accessibilityActions` and `onAccessibilityAction` are optional, so the M1 type stays compatible.
5. **Segmented targets were 40 pt.** A 2 pt vertical `hitSlop` per segment brings each to 44 pt.

## Intl polyfill (coordinator decision after review)

The merged app crashed on launch because Lingui plurals call `new Intl.PluralRules`, which Hermes lacks. Approved: `@formatjs/intl-pluralrules` plus the formatjs packages it strictly needs on Hermes. Ownership extended to `apps/mobile/src/polyfills.ts`, `apps/mobile/package.json` and `pnpm-lock.yaml`.

### What was polyfilled

- `@formatjs/intl-pluralrules` 6.3.15 (`polyfill.js`, installs only when the engine lacks `PluralRules`).
- `@formatjs/intl-locale` 5.3.12 (`polyfill.js`, same rule). The plural-rules polyfill resolves region-tagged locales (`en-US`, `zh-CN`; every app locale has a region) through `@formatjs/intl-localematcher`, whose best-fit path calls `new Intl.Locale(…).maximize()`. Without it, `new Intl.PluralRules("zh-CN")` throws, so it counts as strictly required. It pulls in `@formatjs/intl-getcanonicallocales` and `@formatjs/intl-supportedvaluesof` as its own dependencies. Their polyfills are not installed (`getCanonicalLocales` is native; `supportedValuesOf` was not in scope).
- Locale data: one plural-rules file per language of `apps/mobile/locales/*.po`. That is 52 files for 55 catalogs: `pt-BR` uses `pt`, `pt-PT` has its own file, `zh-CN`/`zh-TW` use `zh`, `en-GB`/`en-US` use `en`. They are imported statically. Lazy loading for the active locale would need a hook in `src/i18n` (outside this ownership), and Metro puts every `require` in the one bundle anyway; the files are 1–3 KB each.
- After the polyfill, on both platforms: `en` 1/2 → one/other; `ar` 3/11 → few/many; `ru` 2/5 → few/many; English ordinal 2 → two; `en-US`, `de-DE`, `pt-BR`, `zh-TW` and `ar-SA` all resolve (`ar-SA` 2 → two).
- `pnpm add` also wrote a `catalog:` entry into root `pnpm-workspace.yaml`. I reverted that (root manifest, outside ownership) and pinned the ranges in `apps/mobile/package.json`. `pnpm install --frozen-lockfile` passes.
