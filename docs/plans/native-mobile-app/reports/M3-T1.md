## Decisions

1. **The redirect URI is `https://rxresu.me/auth/native-callback` for every server, not `https://<server host>/…`.**
   - The app can only receive https callbacks for its associated domain: `applinks:`/`webcredentials:rxresu.me` in `app.config.ts`, and the Android `autoVerify` filter for rxresu.me. A self-hosted host can never be one of them.
   - DCR on any server accepts it: `isAllowedOAuthRedirectUri` allows public https hosts. Checked without the unsafe flag: `true` for this URI, `false` for the private scheme.
   - PKCE makes a code that leaks to rxresu.me useless.
   - The `session.ts` JSDoc is updated. README §1.6 and S3 §1 still say `<server host>`. This is a reviewer/coordinator call if anyone disagrees.
2. **Development fallback (recorded per the brief).** `__DEV__` builds talking to an **http** server register and use `me.rxresu:/auth/native-callback`, the RFC 8252 private-use scheme, as S3 did. This needs `FLAG_ALLOW_UNSAFE_OAUTH_REDIRECT_URI=true` on that local server only. Release builds reject http servers, so they never use it.
3. **Guest login goes through the browser.** "Continue as guest" opens the same authorize URL; the web login page's own "Continue as guest" then creates the anonymous user, and the consent page follows.
   - The app cannot create the guest itself without breaking the upgrade path. The guest cookie must live in the browser's cookie jar, so that "Create account" or "Sign in" there later moves the guest's documents (`anonymous` `onLinkAccount`).
   - Cost: two taps on "Continue as guest" (app, then web). See Follow-ups.
4. **expo-auth-session parses the redirect.** `promptAsync` does it, as S3 proved on both platforms. My code calls no `URLSearchParams.get` and needed no hand-parsing.
5. **Icons:** `hard-drives`, `circle-notch` and a radio glyph are not in the M1 icon map (`src/ui/icon.tsx`, not mine). I used `globe-simple`, `ActivityIndicator`, and `check-circle`/`circle`.

## Round 5: final check 9fae76e4 (2 blockers, fixed)

1. **Sign-out never stops halfway.**
   - Each cleanup step (drafts, the kv sweep, every registered cleanup) runs in turn; a failure is collected and the next step still runs.
   - The tokens and marker are then always deleted, and the session always ends `signed-out`. If the token delete fails, a refresh marker is written so the next launch expires the session instead of signing back in.
   - Collected failures are thrown afterwards as `SignOutCleanupError`, an `AggregateError`. The AU8 sheet shows "Signed out, but some data on this device couldn't be removed."
2. **`invalid_client` always expires.** In the refresh error path, `forgetClient()` is wrapped and `expire(account)` runs in `finally`. The sign-in code-exchange path ignores a `forgetClient()` failure too, so the original error surfaces.

## Round 4: second review 9fae76e4 (4 blockers, all fixed)

Merged `mobile/native-app` first (clean).

1. **Fragment parameters.** `parseAuthorizationResponse` (`oauth.ts`, replaces `parseRedirectParams`) reads only the query. It throws on a repeated `code`, `state`, `iss`, `error`, `error_description` or `error_uri`, and on any of them in the fragment. `authorize()` turns that into `invalid_response` with no code exchange.
2. **Fail closed after a refresh.** A refresh token counts as spent the moment it is sent: it is removed from memory before the request goes out. Concurrent callers wait for that refresh rather than sending it themselves.
   - Only "new tokens stored, then marker deleted" leaves the session signed in.
   - Anything else expires the session: no answer, the 20 s timeout, any error answer (including `server_error`, which round 3 still tolerated), or a failed SecureStore write or delete.
   - Offline (per `expo-network`) still sends nothing and keeps the session.
3. **Marker outlives the tokens.** `expire()` and the restart path call `retireTokens()`, which deletes the stored tokens first and the marker only if that succeeded.
   - On launch, any refresh marker (matching or not) means `expired`. Nothing is sent.
4. **Late sign-ins.** Each `signIn()` takes an attempt number; `signOut()` bumps the counter synchronously when called, as does a newer sign-in. A server switch is sign-out then sign-in, so it is covered too.
   - The commit, in the transition queue, checks the attempt is still current.
   - A stale attempt returns false, revokes its fresh refresh token (best effort) and stores nothing.

**Sign-out cleanup of other features' data.**

- After `clearDraftsFor(scope)`, `signOut()` deletes every `expo-sqlite/kv-store` key under:

1. **Mix-up attack.**
   - `discover()` requires the metadata `issuer` and every endpoint (authorize, token, registration, revocation) to be on the chosen origin; otherwise it throws `ServerError("mismatch")` with its own message. Better Auth's issuer is `<origin>/api/auth`, so the check compares origins.
   - `authorize()` binds the attempt to its `state`, the discovery `issuer`, the PKCE verifier and the redirect. It parses the redirect itself (`parseRedirectParams` in `oauth.ts`, hand-written, no `URLSearchParams`) and rejects a different `state` (`state_mismatch`).
   - **`iss`:** when the server advertises `authorization_response_iss_parameter_supported`, the redirect's `iss` must equal the issuer; otherwise any `iss` present must match. Failure is `issuer_mismatch`, with no code exchange.
   - **Better Auth 1.7.7** (`@better-auth/oauth-provider` `authorize-*.mjs`) advertises `authorization_response_iss_parameter_supported: true`. It sets `iss` on the code redirect (`redirectUriWithCode.searchParams.set("iss", getIssuer(...))`) and on error redirects (`formatErrorURL`), so production servers always take the strict path.
   - **Expo's parser** (`QueryParams.getQueryParams`) spreads `new URL(...).searchParams` and uses `URLSearchParams.forEach` for the fragment, never `.get`. The app no longer depends on it: the code, `state`, `iss` and `error` come from the hand-written parser.
2. **Account-bound retry.**
   - Every sign-in, sign-out and expiry changes a session `identity` number; a refresh does not.
   - `Credentials` carry `account` (the identity they came from). `recoverFromUnauthorized` returns null (no refresh, no retry) when the account changed.
   - The single-flight refresh is keyed by account, and its result is dropped if the identity moved while it ran.
3. **One transition queue.**
   - Sign-in commit, sign-out, refresh, expiry and `saveTokens` run through `transition()`, one at a time in call order.
   - `signOut()` snapshots the departing server, tokens, scope and identity, then: revoke that refresh token → `clearDraftsFor(that scope)` → delete that server's tokens and refresh marker. Memory changes only if the identity is still the departing one.
   - A sign-out queued behind a refresh revokes the rotated token, not the consumed one.
4. **Lost refresh answer.**
   - Before a refresh is sent, a SecureStore marker records a fingerprint of the refresh token (FNV-1a, never the token itself).
   - Each outcome:

     | Outcome | Result |
     | --- | --- |
     | New tokens saved | marker deleted |
     | The server answered with an error (`TokenError`; nothing was rotated) | marker deleted; `invalid_grant`/`invalid_client` still expire the session |
     | No answer (network error, or the new 20 s timeout) | the token is never sent again; session `expired` (re-auth) at once |
     | Restart with the marker matching the stored refresh token | `restoreSession` sets `expired` and deletes the tokens, without replaying |

   - Offline (per `expo-network`), no refresh is sent and the old token is used, so a dead connection does not end the session.
5. **Query caches.**
   - `subscribeIdentity()` fires synchronously on every account change (sign-in, account or server switch, sign-out, expiry).
   - `SessionGate` cancels and clears the React Query cache there, before the new state renders. Expiry clears it too, so the screen behind AU8 shows no server data.

## Follow-ups

- **M7-T1:** Settings' `SignOutRow` treats any `signOut()` rejection as "Couldn't sign out. Try again." and skips its own navigation. A `SignOutCleanupError` means the user *is* signed out; the gate has already gone to sign-in. For "Switch server" the row should still continue to the server picker and show the partial-cleanup message.
- **Coordinator:** the M5-T1 harness fails on `mobile/native-app` itself (`verify.mjs:188`, "manual save blocks double tap").
- **Fail-closed cost:** a token-endpoint error answer or a dropped connection during a refresh now ends the session (re-sign-in). Offline devices are spared by the `expo-network` check.
- If local data cannot be cleared during sign-out, the refresh token is already revoked (the review's order is revoke → clear → delete). The user stays signed in until the access token lapses, then sees AU8, and sign-out can be retried.

- **Coordinator / M1 / M3-T2:** Hermes has no `Intl.PluralRules`, and the Documents library crashes on plural messages (above). Add a polyfill or plural fallback.
- On a signed-out launch, the initial route renders Documents for a frame before the gate redirects. The crash above comes through that frame too. The gate's redirect needs a mounted navigator; an `app/index.tsx` redirect by session status would avoid the frame.

- **One-tap guest:** a small web change. The login page could start anonymous sign-in itself when the OAuth query asks for it, for example `prompt=guest`, which `redirectToOAuthLogin` already forwards in `callbackURL`. The app would then add that parameter.
- **Sign out from AU8 discards unsynced edits without a confirm.** Settings has one (ST8); the expired sheet does not. Add one if the owner wants it.
- **Session lifetime:** SV4 server behaviour (offline_access tokens outlive the browser session) is assumed merged, so the 7-day limit from S3 §4 no longer applies. Not re-tested here.
- **M2-T1:** the AU7 toast sits over the sign-in server row, because the Toaster's offset is for the tab bar.
- **M2-T1:** add `hard-drives` to the icon map for the server rows, as in the mockup.
- Settings → Sign out / Switch server (ST8) is M7. It only needs `signOut()`; the gate handles navigation and the toast.
