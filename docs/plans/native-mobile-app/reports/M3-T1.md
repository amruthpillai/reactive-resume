- **`src/auth/session.ts`**: every M1 export keeps its signature.
  - `authorize`: discovery, then DCR, then `AuthRequest.promptAsync(discovery, { preferUniversalLinks: true })`, then `exchangeCodeAsync`. `resource=<origin>` is sent on authorize, code exchange and refresh.
  - Refresh: still single-flight. `invalid_grant` or `invalid_client` deletes the tokens and sets `expired`. A network or server error returns the old token, so the request fails the way it would have. A result that arrives after sign-out or a server switch is discarded.
  - `signOut`: waits for an in-flight refresh, revokes the refresh token (best effort), then deletes the tokens. The server and the cached client are kept.
  - New exports: `hasChosenServer()` (first launch shows the server picker) and `cancelSignIn()`.
- **`src/auth/oauth.ts`**: discovery (cached per origin), DCR with the S3 §1 body, `client_id` cached in SecureStore under `client.<hex(origin)>` and forgotten on `invalid_client`, the redirect URI, `toOrigin`, `getFlags`.
- **`src/auth/session-gate.tsx`**: `SessionGate` is the route guard plus AU7 and AU8.
  - Signed out outside `(auth)`: go to sign-in, or to the server picker on first launch.
  - Signed in on an `(auth)` screen: go to Documents.
  - `expired`: the AU8 sheet over the current screen, which cannot be swiped away (it re-presents). It offers Sign in again and Sign out.
  - After a sign-out: the AU7 toast "Signed out of {host}. Your documents are still there."
- **`app/(auth)/auth/native-callback.tsx`**: on Android the callback URL also reaches expo-router. This route steps back, so the router never shows "unmatched route".

## Decisions

1. **The redirect URI is `https://rxresu.me/auth/native-callback` for every server, not `https://<server host>/…`.**
   - The app can only receive https callbacks for its associated domain: `applinks:`/`webcredentials:rxresu.me` in `app.config.ts`, and the Android `autoVerify` filter for rxresu.me. A self-hosted host can never be one of them.
   - DCR on any server accepts it: `isAllowedOAuthRedirectUri` allows public https hosts. Checked without the unsafe flag: `true` for this URI, `false` for the private scheme.
   - PKCE makes a code that leaks to rxresu.me useless.
   - The `session.ts` JSDoc is updated. README §1.6 and S3 §1 still say `<server host>`. This is a reviewer/coordinator call if anyone disagrees.
2. **Development fallback (recorded per the brief).** `__DEV__` builds talking to an **http** server register and use `me.rxresu:/auth/native-callback`, the RFC 8252 private-use scheme, as S3 did. This needs `FLAG_ALLOW_UNSAFE_OAUTH_REDIRECT_URI=true` on that local server only. Release builds reject http servers, so they never use it.
3. **Guest login goes through the browser.** "Continue as guest" opens the same authorize URL; the web login page's own "Continue as guest" then creates the anonymous user, and the consent page follows.
   - The app cannot create the guest itself without breaking the upgrade path. The guest cookie must live in the browser's cookie jar, so that "Create account" or "Sign in" there later moves the guest's documents (`anonymous` `onLinkAccount`).
   - Cost: two taps on "Continue as guest" (app, then web). See Follow-ups.
4. **expo-auth-session parses the redirect.** `promptAsync` does it, as S3 proved on both platforms. My code calls no `URLSearchParams.get` and needed no hand-parsing.
5. **Icons:** `hard-drives`, `circle-notch` and a radio glyph are not in the M1 icon map (`src/ui/icon.tsx`, not mine). I used `globe-simple`, `ActivityIndicator`, and `check-circle`/`circle`.

## Round 2: coordinator items

Ownership extended by the coordinator to `app/_layout.tsx` (one mount), `src/api/client.ts`, and the `src/draft` call sites.

- **SessionGate mounted** in `app/_layout.tsx`, after `<RootStack />`.
- **Redirect URI** decision accepted; documented in the `redirectUri` comment in `oauth.ts`. **Guest through the browser** accepted for v1; the one-tap web change stays a follow-up.
- **1. Atomic credentials** (`src/api/client.ts`, `session.ts`):
  - `getCredentials()` returns the server, its access token and its account scope from one session read. If the server changes during a refresh, the token comes back null rather than another server's token.
  - `RPCLink` now builds URLs against a placeholder origin (`https://server.invalid`). `rpcFetch` puts the snapshot's server and token on the request, so `/api/rpc` and `rest()` can no longer pair one server's URL with another's token.
  - A per-call `ClientContext` `{ scope }` binds a call to one account. The draft adapters pass the draft's scope on `update`/`import`; a write whose account is no longer current fails with `SessionChangedError` before it leaves the device, so a queued draft can never reach another server or account.
  - **401 recovery**: a 401 whose body is `UNAUTHORIZED` (not `NEED_PASSWORD`) to a token that looked valid calls `recoverFromUnauthorized`. That retries with a newer token if another request already refreshed; otherwise it refreshes once (the shared single flight) and retries once. A second 401 calls `rejectCredentials`, which marks the session `expired`. Request bodies are buffered so the retry can resend them; `rest()` callers must pass repeatable bodies (all current ones do: `FormData`).
- **2. Offline cold start**: `getAccountScope()` returns `JSON.stringify([server, sub])`, M3-T3's exact scope format. It is read from the stored access token at restore or sign-in, with no refresh and no network. `src/draft/native.ts` `scope()` now uses it. It is null unless signed in, so an `expired` session still suspends drafts, as M3-T3 designed.
- **3. Sign-out cleanup**: `signOut()` calls `clearDraftsFor(scope)` (dynamic import of `@/draft/runtime`, which avoids the module cycle) before revoking and discarding tokens. The scope is kept through `expired`, so "Sign out" from the AU8 sheet still clears that account. A cleanup failure throws and leaves the user signed in; Settings and AU8 show "Couldn't sign out. Try again."
- **4. Server rule**: `isAllowedServer(origin)` accepts https, plus `http://localhost`, `127.0.0.1` and `10.0.2.2` (any port) in `__DEV__` only. The server picker, the sign-in screen's `?server=`, `signIn()` and `restoreSession()` (a stored server that fails the rule falls back to rxresu.me) all apply it. Every server reaching `getServer()` has passed it, so the Settings browser hand-offs can trust `getServer()`.
- **5. Not mine to change**: the Toaster offset over the sign-in server row (M2-T1, `src/ui`), and adding `hard-drives` to the icon map (`src/ui/icon.tsx`, M2-T1). Both are noted for M2-T1.
- **Sign-out navigation**: Settings (`SignOutRow`, M7-T1) navigates after `signOut()` resolves, to the server picker for "Switch server". The gate now redirects in the same tick as the status change (`subscribeSession`), so the caller's navigation always wins and nothing overrides it a frame later.
- New session exports: `getCredentials`, `recoverFromUnauthorized`, `rejectCredentials`, `getAccountScope`, `getSession`, `subscribeSession`, and the `Credentials` type. The M1 exports are unchanged.
- `reports/M3-T3/verify.mjs` (M3-T3's harness) stubbed `@/auth/session` with `getServer` and `getAccessToken`. Its stub now provides `getAccountScope`, with the same derivation. 24/24 scenarios pass.

## Follow-ups

- **Coordinator / M1 / M3-T2:** Hermes has no `Intl.PluralRules`, and the Documents library crashes on plural messages (above). Add a polyfill or plural fallback.
- On a signed-out launch, the initial route renders Documents for a frame before the gate redirects. The crash above comes through that frame too. The gate's redirect needs a mounted navigator; an `app/index.tsx` redirect by session status would avoid the frame.

- **One-tap guest:** a small web change. The login page could start anonymous sign-in itself when the OAuth query asks for it, for example `prompt=guest`, which `redirectToOAuthLogin` already forwards in `callbackURL`. The app would then add that parameter.
- **Sign out from AU8 discards unsynced edits without a confirm.** Settings has one (ST8); the expired sheet does not. Add one if the owner wants it.
- **Session lifetime:** SV4 server behaviour (offline_access tokens outlive the browser session) is assumed merged, so the 7-day limit from S3 §4 no longer applies. Not re-tested here.
- **M2-T1:** the AU7 toast sits over the sign-in server row, because the Toaster's offset is for the tab bar.
- **M2-T1:** add `hard-drives` to the icon map for the server rows, as in the mockup.
- Settings → Sign out / Switch server (ST8) is M7. It only needs `signOut()`; the gate handles navigation and the toast.
