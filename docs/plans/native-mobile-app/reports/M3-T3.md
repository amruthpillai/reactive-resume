# M3-T3: draft store and saving

Status: succeeded. Branch: `mobile/M3-T3`. Base: `mobile/native-app` @ `9e36288cf`. No push.

## Delivered

- Implemented the existing `DraftStore` contract for resumes and cover letters, without editing `types.ts` or other M1 contracts. No dependency, manifest, lockfile, route, catalog, shell or server changes.
- Resume saves debounce for 500 ms; letter saves for 800 ms. One `sessionId` per editing visit, retained with an unsaved draft. Flush waits for an in-flight save and drains newer edits before returning. Save responses retain newer typing and server-owned timestamps/revisions; resume data references survive autosave.
- Undo/redo holds 200 steps. Keyed typing coalesces for 1 second, unkeyed edits for the web's 500 ms, `newStep` separates structural edits, and `sameStep` joins a multi-edit action. New edits invalidate redo; external rebases clear history. `updateDocument` metadata changes survive later letter content undo/redo.
- Each edit synchronously persists the baseline, latest document and session ID in `expo-sqlite/kv-store`. Keys begin `reactive-resume:unsaved:` and include server origin, OAuth subject, document kind and ID. Tokens are never persisted there or logged. Dates and schema data are validated/restored before use. Disk-write failures remain errors and retain an in-memory draft across navigation for retry.
- Offline queues survive restart and replay on `expo-network` reconnect, including documents whose editor was closed. Resume and letter listeners each handle a reconnect, without one listener consuming the transition for the other. Failed, locked and conflicting queued documents stay local until reopened/resolved. Session ownership is checked before writes and after asynchronous results.
- Resume updates send `expectedUpdatedAt`; `RESUME_VERSION_CONFLICT` loads the remote copy and pauses saving. Letters send `expectedRevision` and handle `CONFLICT`. Keep mine omits the resume timestamp check; letters use the freshly fetched remote revision because their API requires one. Use theirs discards local edits only after confirmation. Keep both imports the unsaved local content as a separate private document, then loads the remote original here, matching the M1 contract. A returned copy ID is retained if a subsequent metadata save fails.
- Resume SSE uses `streamClient.resume.updates.subscribe`, reconnects after 2.5 seconds, and aborts on close/switch. Remote content waits for field blur; remote notifications never advance an unsaved draft's baseline. Late refreshes cannot replace a different document opened meanwhile. Letters refresh on foreground/reconnect or explicit refresh; the server has no cover-letter update subscription endpoint.
- `AppState` background/inactive events flush pending work. Field blur and editor close flush too. Locked documents reject edits and undo/redo while retaining unsaved local content.
- Conflict UI uses native `Modal`, token styling, and `src/ui` controls. Back/backdrop/swipe do not dismiss the required choice. Use theirs has a destructive confirmation; locked documents disable Keep mine. All user-facing strings use Lingui macros; extraction is left to the coordinator.

## Integration surface for subsequent builders

Import from `@/draft`:

- `useResumeStore` / `useLetterStore`: Zustand bound stores exposing exactly the M1 `DraftStore` state/actions. Select `data`, `document`, `status`, `locked`, `conflict`, `canUndo` and `canRedo`; there is no web-specific `.resume` alias.
- `useResumeDraft(id)` / `useLetterDraft(id)`: mount once in the owning builder, above pane switches. They open/close the document, react to session/account changes, preserve history through same-account token refresh, and return the store. Loading/open failures appear through `document === null` and `status`.
- `useCurrentResume`, `useCurrentLetter`, `useResumeData`, `useLetterData`, `useUpdateResumeData`, `useUpdateLetterData`, `useIsResumeLocked`, `useIsLetterLocked`, `usePatchResume`, `usePatchLetter`.
- `resumeFieldFocus` / `letterFieldFocus`: spread `onFocus` and `onBlur` onto native text and enriched-HTML editors. If a screen has its own handlers, call these alongside them. Rich-text focus is separate from `TextInput.State`; forwarding these events is required for reliable deferred remote updates.
- `useResumeUpdateSubscription` / `useLetterUpdateSubscription`: explicit refresh on mount; `open` already owns the resume SSE stream, so callers do not create a second subscription.
- Render `ResumeConflictSheet` / `LetterConflictSheet` once in the builder. `DraftConflictSheet` also accepts explicit props for an independent host. The existing status slot consumes `status`; Retry calls `retry()`.

`close()` stops the document SSE subscription after flushing. The offline queue keeps lightweight platform listeners after the first open so closed documents can replay. Session suspension removes those listeners. Nothing was mounted into another builder's owned routes/layouts.
