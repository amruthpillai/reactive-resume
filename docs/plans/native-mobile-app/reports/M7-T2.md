## Delivered

### Public resume viewer: `app/r/[username]/[slug].tsx` → `src/features/public/**`

- `resume.getBySlug` through the shared `client` (bearer when signed in, so owners also see their private resumes). An old slug redirects to the current one with `router.replace` (web loader behaviour).
- Native reflow (`resume-reflow.tsx`, frames P1/P1b): web's `reflow.ts` and `resume-reflow.tsx` ported. Section and entry order come from `@reactive-resume/pdf/semantic-tree` (`buildSemanticTree`, `shouldShowResumeHeader`), titles from `@reactive-resume/pdf/section-title`. Both are pure TS that S2 proved on Hermes; the export bundles them. The same per-type `SHAPES`, roles, keywords, reference phones and contact pills apply. Contact pills and links are tap targets through `Linking`, limited to `http(s)`, `mailto` and `tel`. Text sits on `paper`/`paperInk`/`paperLine`. The section accent is the resume's primary colour, darkened to 70% when its contrast on white is under 4.5 (the native form of web's `color-mix`). RTL comes from the resume locale, and text is selectable.
- Rich text: React Native has no `DOMParser`, and `node-html-parser` is not a mobile dependency. `html.ts` is a small tokenizer that keeps only formatting tags (p, headings, lists with nesting and markers, blockquote, strong/em/u/s/code, br) and safe links. Scripts, styles and comments are dropped; other tags keep only their text; entities are decoded. Owner HTML is never rendered as markup.
- Password prompt (P3): `resume.verifyPassword`. As S3 §6 found, `expo/fetch` keeps the `resume_access_<id>` cookie in the native cookie store, so a refetch unlocks without app code. A wrong password shows the inline error and the field keeps focus; other errors show the web toast copy. Return runs Unlock, and the button shows a spinner while verifying. Autofill and keychain saving are off: it is someone else's password.
- Download PDF (P2/P2b/P2c): `GET /api/resumes/{username}/{slug}/pdf` (`handlePublicResumePdf`, web's fallback path) through `expo/fetch` with `credentials: "include"` (the unlock cookie) and the bearer token. The PDF is written to the cache (one file per name) and handed to `expo-sharing`, which covers Save to Files on iOS and the Sharesheet on Android. `resume.statistics.recordDownload` is then sent fire-and-forget, as web does.
  - While downloading, the button reads Downloading… and ignores further taps.
  - On failure, a toast with Retry; offline gets its own copy.
  - A 401 means the 10-minute unlock expired, so the password prompt returns.
  - With downloads off (P1b), Share fills the bar.
- Share: the native share sheet with `${server}/${username}/${slug}`.
- Loading skeleton in the reflow shape (P5). Not shared, unknown or trashed (P4): the same empty state with Close. Network failure: "You're offline. This resume opens when you reconnect." with Try again.

### ATS checker: `app/ats-checker.tsx` → `src/features/ats-checker/**`

- Choose a PDF (A1): `expo-document-picker` filtered to PDF. "Check a sample file" downloads `${server}/templates/pdf/onyx.pdf` to the cache (the file web uses). The job posting field is capped at 20,000 characters. The copy reads "checked on the server and not stored", per the owner answer in the ledger.
- Before uploading (`check.ts`): a size check (25 MB), a `%PDF` magic-byte check, and an `/Encrypt` scan of the trailer. The server answers 400 for both unreadable and encrypted files, so the password-protected message (A2) has to come from this local check. Offline gets "You're offline. Connect to check a file." Then `POST /api/openapi/pdf-checks` as multipart through `rest()`; 413, 429 and 400 map to the A2 copy.
- Checking (A3): three steps with Cancel, which aborts the upload. The server sends no progress, so "Checking layout and content" starts 1.5 s into the upload. This is marked in the code.
- Report (A4/A4b/A4c/A5/A6):
  - An SVG score ring (`react-native-svg`) with the verdict thresholds 80 and 50. The ring is drawn filled, without a sweep animation.
  - The issue count uses `plural`.
  - A truncation banner when the server read fewer pages than the file has.
  - Category accordions, worst first: web's `issueRows`, with Writing marked "Not scored". The first row starts open.
  - When a posting was pasted, "Terms from the posting" lists missing and covered term chips, plus the empty and all-found copy.
  - A segmented Report / "As software reads it" switch. The extracted text is monospaced, selectable and scrolls horizontally.
  - Finding copy comes from `messages.ts`, a port of web's file: an exhaustive `switch` in place of `ts-pattern`, with identical msgids so the catalogs share translations.
- Fix these in the editor (A7): reuses M3-T2's `importDocument(asset, aiAvailable=false, aiPdf=false, signal)`, which uses server text extraction (the same reading as the check), then `router.replace(routes.builder(id, "check"))`.
  - Signed out: the file is kept in a ref, the screen pushes `sign-in`, and the import continues when the session becomes `signed-in` and returns here.
  - Files over 10 MB get the A4d bar (Check another file / Start blank → New) and never upload a second time.
  - Import errors show `ImportError` messages or "Couldn't import the file. Try again from Documents."

### Search: `app/search.tsx` → `src/features/search/**`

- Full-screen search with the command palette's structure (Q1–Q6):
  - First page: "Search for…" (Resumes, Applications, Assistant conversations), "Go to…" (New document, Trash, ATS Checker, New Application, Settings) and "Preferences" (Change theme to…, Change language to…).
  - While typing: results grouped as Resumes, Letters, Applications, Assistant conversations and Actions, at most three per kind with "Show all". Actions also match Documents, Applications, Account, Preferences and AI & developer.
  - "Ask the assistant “…”" is always last.
  - Empty state: "No commands match that search." (Q3), with Ask still available.
  - Scoped pages: Resumes with "Create a new resume"; Applications with "New Application"; conversations of document scope only, as web.
  - Loading rows: Loading resumes… / applications… / conversations….
  - Theme page: Light, Dark, Match system, through `setThemePreference`. Language opens Settings → Preferences, which owns the RTL reload.
- Ranking (`rank.ts`, pure): every query term must match. Prefix beats word start, which beats substring. Title matches outrank keyword matches (tags, linked company and role, thread document). Case and accents are ignored. Ties go to the most recently edited, then by title. Signed-out users see only the ATS Checker and the theme rows.
- Data:
  - M3-T2 `useDocuments()` and M5-T1 `useApplications()`, so they share those cache entries.
  - `agent.threads.list`, keyed by server, is fetched only while typing or on the conversations page.
- Keyboard and back:
  - Autofocus with the search return key; Return opens the first result.
  - Drag dismisses the keyboard.
  - Back order follows web's Backspace: clear the field, then leave the scoped page, then close. This applies to Backspace in an empty field, the field's back button and Android hardware back. iOS shows Cancel beside the field.
- Navigation uses `router.dismissTo`: the modal closes onto an existing tab instead of stacking a second `(tabs)`.

## Review fixes: Codex `7f77db95`

FIXED 5. First `git merge mobile/native-app`: a clean merge that brought in M3-T4.

1. **The `/pdf-checks` response shape.** `checkPdf` returns `pdfCheckSchema.extend({ fullText })`, a flat report. `check.ts` now splits `{ fullText, ...report }` into `{ report, fullText }`, which is what the checker renders.
2. **Quadratic tokenizer.**
   - The tag pattern stops at the next `<` (`[^<>]*`), and a tag name must end at whitespace, `/` or `>` (lookahead). A failed match therefore never rescans the rest of the string.
   - An unterminated comment swallows the rest of the input, as browsers do.
   - Entity names and numbers are bounded.
   - Input is capped at 200,000 characters.
   - The mark stack and list depth are capped at 16; overflowing marks are counted, so their closing tags stay balanced.
   - New scenario 10 runs seven hostile inputs (`"<a".repeat(40000)`, `"<!--"`, an unterminated attribute, `"<p>"`, 40,000 nested `<strong>`, `"&#"`, 20,000 nested lists). Each must finish in under 500 ms with depth ≤ 16, and broken markup must still read as text.
   - Negative control: the previous parser took 4,674 ms on `"<a"` and 1,031 ms on nested `<strong>`.
3. **Pending import.**
   - The pending file now records the server and the time of the Fix press.
   - It is cleared by Cancel, Check another file and any new check.
   - It resumes only when the session is signed in on the same server within 10 minutes. On a sign-in or server switch that doesn't qualify, it is dropped, never imported.
4. **Download files.**
   - Each download writes to its own folder under `cache/public-resume-pdf/<time>-<random>/`, keeping the readable file name.
   - Before the next download, every older folder except the latest is deleted, so a share target can still read the most recent file. Delete failures are skipped and retried next time.
5. **Resume search** includes `document.slug` in the keywords, as web matches name and slug.

Also in this round:

- **Assistant links** now match M6-T3's route, as described under Contracts. One real fix: a thread with both a working resume and a letter used to open the assistant. It now opens the letter, as M6-T3 does.
