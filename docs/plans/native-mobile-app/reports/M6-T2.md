## Transcription transport (decision, flag for review)

`career.voice.transcribe` takes `audio: z.file()`. The mobile oRPC link buffers the request with `request.arrayBuffer()`, and a `FormData` body can't be read that way. Its RPC serializer also sends only real `Blob`s as files, and expo-file-system's `File` is not one. So mobile calls the same procedure through its OpenAPI route: `rest("/career/voice/transcribe", { method: "POST", body: FormData })`, with `providerId`, `model`, `applicationId` and `audio`. Expo's FormData sends the audio part from `file.bytes()` with an explicit name and type (`audio/mp4` for `.m4a`). The file's own type can read `audio/x-m4a`, which the server rejects. `voice.speak` and `saveTranscript` use the oRPC client. This is unproven against a live server (see Skipped).

The scenarios import the shipped pure module `src/features/workspace/logic.ts` directly (Node 24 type stripping):

- **Audio size cap:** exactly 2 MiB passes; one byte more, empty, or unknown size are refused.
- **Recording preset:** 2 minutes stays under the cap with 25 % headroom for the container.
- **Chosen files:** `audio/x-m4a`/`m4a`/`x-wav` are normalised; video, unknown or oversize files are refused.
- **Voice choice:** the stored connection is kept while capable; Text only; Groq has no speech; a retired model falls back.
- **Prepare phase:** the plan / soon / after boundaries, including a running interview.
- **Current interview:** the next one, else one that ended in the last day, else none.
- **Week plan, 18:00 local:** today only while 18:00 is ahead, Berlin across 25 Oct. Auckland on the eve of its DST change: web's single-pass offset lands at 05:00Z (17:00 local), an hour early; the two-pass port gives 06:00Z.
- **Proposed changes:** fixed rows and the default ticks.
- **Tighten diff:** the parts rebuild both texts.
- **Write numbers as digits:** ranges, percentages, and small numbers kept as words.
- **Answers download:** the Markdown and text bodies.

Test-audit gate: no Vitest suite was added. The scenarios guard client-only logic that a regression would break silently: an over-cap upload attempted, the wrong reminder evening, wrong default ticks, and mangled transcripts. Server and web suites can't reach that logic. There are no test-only seams.
