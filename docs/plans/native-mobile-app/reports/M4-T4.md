# M4-T4: Cover letter editor

Status: succeeded. Branch `mobile/M4-T4`, base `mobile/native-app` @ `2f5b3b683`. No push. JS only: no native build, simulator or emulator.

## Delivered

The letter editor now has the mockup's Write / Page / Design panes (builder.html L1–L7). Logic is ported from `apps/web/src/features/letters/**` and `apps/web/src/routes/builder/letter/**`.

- **Write** (`src/features/letters/write.tsx`):
  - **For:** the linked application card (company initial, role, company, stage dot and label) with Change. Without a link: "Link an application". The picker is a sheet with search, "No application" and the empty state. Closed applications are hidden unless already linked. Linking fills the recipient company and the first contact on structured letters.
  - **To:** Name or team (placeholder "Hiring team"), Company, and Date on the system picker, with "No date" to clear it. Freeform letters keep a rich-text recipient.
  - **From:** a resume picker, plus the "Use details from “…”" switch (live or copied). A letter taking a resume for the first time links both details and design. "No resume" unlinks both.
  - **Letter:**
    - Greeting and Sign-off are plain text. They default from the recipient and the document locale, and offer "Use default" once edited.
    - The body is rich text.
    - Body empty: the draft offer worded by context (posting and resume, resume only, posting only, or neither).
    - No usable provider: "Drafting needs an AI provider" opens `AIProviderSetupSheet`.
  - **AI draft:** streamed over SSE (`streamClient.coverLetters.draft`) on a green wash.
    - While streaming, a caret shows; with reduced motion, "Drafting…" shows instead. The keyboard is dismissed. Stop is offered.
    - When the draft is ready: Keep, Shorter, More personal, Discard. Keep is one undo step and shows the toast "Draft kept. Edit anything you like."
    - On failure: the provider is named on `BAD_GATEWAY`, with Try again (repeats the last request) and Dismiss.
  - **Length:** the word count against the 180–320 band (450 scale), with web's four messages. While a draft shows, it counts the draft.
  - **Design note:** "Matches the resume (Onyx, Balanced type, Moss)." with a link to Design.
  - **Locked banner:** the letter's copy points to Documents, because mobile letters have no document menu.
- **Page** (`src/features/letters/page.tsx`, `app/letter/[id]/page.tsx`):
  - Uses the M3-T4 pipeline through `usePreview(letterPageData(letter, words), undefined, { renderOptions: { includeCoverLetterHeader: true } })`.
  - Shows `expo-image` pages with a crossfade (none with reduced motion), a zoom bar (60–150%, Fit, page count), retry on errors, and the lost-characters warning.
  - A streaming draft shows on the page, throttled to 400 ms as on web. There is no line selection, per mockup L5.
  - On tablet, the layout renders this screen beside the panel.
- **Design** (`src/features/letters/design.tsx`):
  - "Matching the resume" switch, or the no-resume note. While linked: "Change the resume's design" opens the resume builder's Design.
  - With its own design: Template (17), Type (5 pairings, text size 9–12.5 pt), Color (8 accents and a hex field), Page (A4 / Letter / Free-form, margins).
  - Editing any of these ends the design link, matching the server rule.
- **Share & export** (`src/features/letters/share.tsx`): a sheet opened by Share in the letter chrome, with Download and History tabs (L7).
  - Download formats: PDF (rendered locally; works offline), Resume + letter (two matching PDFs, both built before either is handed off), Word, OpenDocument, Markdown, JSON. Exports reuse M4-T3's `exportFile`, `exportDirectory`, `shareExport` and `letterWords`, so server formats get the document-language `words`.
  - Download also has the file name field, failure with "Download PDF instead", and the offline banner. It flushes the draft before server work.
  - History: name and save a version, Now, the version list (named versions have an always-visible ⋯ with Rename… and Delete), a read-only page view, and Restore. The server writes "Before restore"; restore then reopens the draft (`open`) to reset its baseline and undo.
- **Layout** (`app/letter/[id]/_layout.tsx`):
  - Panes are Write / Page / Design, and `tabletPanes` is Write / Design. `page={<PageScreen />}` and `onShare` opens the sheet.
  - A `DraftChrome` child fills the name and save status (with Retry and Locked) once for every pane. `LetterConflictSheet` is still mounted only here.
  - An AI draft is discarded when the editor closes.
- **Routes:** `LetterPane = "write" | "page" | "design"` (letter pane only).

## Decisions

- **Draft store use:** typing uses `update` with a `coalesceKey` per field. Link changes (application, resume, live details, design link) use `updateDocument` plus an immediate `flush`.
  - This follows web, where these are server changes rather than typing. They stay out of undo.
  - The server's resolved `style` (linked sender and design) comes back through the adapter's `merge`.
- **Draft before streaming:** drafting flushes the letter first, because the server reads the saved letter's links. If the letter changes during the flush, the draft returns to idle.
- **Rich text:** M3-T5 is not merged (`git log mobile/native-app | grep m3-t5` is empty).
  - `src/features/letters/rich-text.ts` ports its pure session: only an edited field is re-serialised, and the `<html>` wrapper fixes iOS short fragments.
  - `rich-text-field.tsx` adds a small editor with a toolbar for bold, italic, underline, lists and Done. There is no Improve, per the mockup.
  - The toolbar renders last in the pane. BuilderChrome already ends content at the keyboard, so no `KeyboardStickyView` is needed.
- **Design presets:** `design-presets.ts` ports the web preset table (pairings, accents, margins, text size). M4-T4 cannot use M4-T1's Design controls, which are parallel and unmerged.
- **Not built:** the mockup's sparkle (assistant) button and the name caret on the letter bar. Neither is in the brief. Letters have no assistant route or document menu.

The Node harness runs the shipped `length.ts`, `drafting.ts` and `rich-text.ts`. It simulates only `@/api/client`'s stream and `@/draft`'s store (through `registerHooks`); zustand and `ORPCError` are the real modules.

- **Word-count guide:** markup and `&nbsp;` are stripped, and the band edges are correct (179 short, 180 and 320 comfortable, 321 long).
- **SSE drafting:**
  - The draft flushes before it streams.
  - Chunks accumulate, and the result is trimmed and ready.
  - Shorter and More personal send `previous`, and the input is recorded for Try again.
  - An empty draft fails. `BAD_GATEWAY` names the provider.
  - Stop aborts the signal and ignores late chunks.
  - A newer draft aborts an older one and wins.
  - Switching letters during the flush never streams and returns to idle.
- **Rich text:** an untouched body keeps its stored HTML byte for byte (including a table and `<strong class>`). Short fragments get the `<html>` wrapper. A kept draft loads into an unfocused body, and typing is never overwritten.

The harness caught one bug before commit: a letter switch during the flush left the draft stuck on "streaming". It is fixed in `drafting.ts`.

**Test-audit gate:** the stream and abort race and the "only edited fields" rule can fail silently, as stale drafts or HTML rewritten without an edit. Web tests can't execute this port. The harness is a manual Node scenario the brief asked for. It adds no Vitest suite and no production seam.

**Screenshots skipped,** as the launch brief instructed (no native dev clients or simulators). Nothing is claimed about device rendering, the SSE stream on Hermes and `expo/fetch`, the rich-text toolbar against the keyboard, share-sheet handoff, or light/dark appearance.
