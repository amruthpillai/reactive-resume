## Better Auth 1.7.7 findings

Read installed `@better-auth/core` Apple provider and Better Auth callback/origin middleware; also queried current Better Auth Apple documentation through Context7.

- Browser Apple sign-in needs a Services ID and a pre-signed client-secret JWT. No additional provider fields are required for this system-browser flow. `appBundleIdentifier` is optional and changes the ID-token audience, so it is deliberately omitted here.
- The provider requests `form_post`; `/callback/:id` supports URL-encoded POST and redirects to its GET callback. The existing Hono adapter accepts every method under `/api/auth/*` and preserves the form body.
- Origin validation needs `https://appleid.apple.com`; the conditional trusted-origin addition handles this without disabling checks.
- Operators must register `${APP_URL}/api/auth/callback/apple` with Apple and renew the client-secret JWT before expiry (at most six months).
