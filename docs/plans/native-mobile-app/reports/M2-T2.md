## Contracts (for M3-T4, M3-T5, M4, M5)

All in `apps/mobile/src/shell/`.

### `useIsTablet()` (`use-is-tablet.ts`)

Returns true when the window is at least 700 pt wide (builder.html: "below 700 pt wide" falls back to the phone layout). It reads the window, not the device, so an iPad in Split View or a narrow Stage Manager window gets the phone layout.

### `useBuilderChrome(slots)` (`builder-chrome.tsx`)

Call it from any screen inside `app/builder/[id]` or `app/letter/[id]`. It draws nothing in place: while the screen is mounted, the shell reads the values. When several screens are mounted, the latest one wins per key. A key disappears when the screen that set it unmounts.

```ts
type BuilderChromeSlots = {
	title?: string; // document name; defaults to "Resume" / "Cover letter"
	save?: { status: SaveStatus; locked?: boolean; onRetry?: () => void }; // the status line under the name
	onMenu?: () => void; // the document menu; makes the name a button with a caret
	onShare?: () => void; // replaces Share (resumes default to routes.share(id); letters have no Share until set)
	shared?: boolean; // "Public" badge on Share
	actions?: ReactNode; // buttons before Share: Assistant on phone; History, Assistant, Download PDF on tablet
	banner?: ReactNode; // under the top bar: the locked banner
	badges?: Partial<Record<pane, number | string>>; // pane-tab badges in `warn`, e.g. { check: 3 }
};
```

- The save line uses web's wording (`save-status.tsx`): Saving…, Saved (also for `idle`), Offline · saved on this device, Not saved · Retry, Locked.
- `status: "offline"` also shows the builder offline strip under the top bar.
- Values that hold for every pane (title, save, shared) should be filled once, not per pane. `BuilderChrome` renders its `children` inside the slot provider and outside the Stack. After M3-T3 merges, add a child component to `app/builder/[id]/_layout.tsx` that reads the draft store and calls `useBuilderChrome({ title, save, shared })`. Pane screens then fill only their own keys (actions, banner, badges).
- Typing in a screen re-renders only the top bar and pane bar, never the Stack.

### `BuilderChrome` (the component the two layouts render)

Props: `panes` (phone tab order), `tabletPanes` (the mode switch), `page` (tablet right side), `title`, `onShare`, `modals` (child routes presented as modals), `children`. It renders the editor's Stack itself:

- Pane routes use the top bar as their header on phone (so it slides with pushes) and no header on tablet.
- Other routes use the default native header.
- On iOS the pane bar stays under modals.

**Page on tablet.** The builder layout renders the `page.tsx` route's default export (`import PageScreen from "./page"`) beside the panel. M3-T4 owns that file; it must read the resume id with `useLocalSearchParams` or `useGlobalSearchParams` (both work from the layout), and must not depend on being the focused route.

### `useWorkspaceChrome(slots)` (`workspace-chrome.tsx`)

Call it from `app/applications/[id]/[tab].tsx`. Slots: `title`, `subtitle`, `actions` (Application details, Ask coach), `context` (tablet column), `banner` (saved-version banner), `badges` (per tab, `ReactNode`). The tab strip switches with `router.replace(routes.application(id, tab))` and reads labels from web's `tabLabel` msgids, including the msg contexts.

### `setAppBanner(key, node | null)` and `AppStrip` (`app-banner.tsx`)

- `setAppBanner` shows a banner above every tab, or hides it with `null`. Keys are free strings; `"session"` and `"guest"` are the expected ones.
- `AppStrip` is the full-width `strip` look in `info` or `warn`, with an optional icon and a trailing action.
- The guest banner in app.html scrolls with the list, so M3-T2 may render it in the list instead.

### Tab badges

Set `tabBarBadge` on a tab with `navigation.setOptions`; nothing new to import. Applications shows a quiet grey count; the other tabs show a filled `accent` count. The sidebar shows the same values.

## Decisions

- **Name menu instead of ⋯.** The brief lists "Share and ⋯". The approved mockup (builder.html `editorBar`) has no ⋯: the document name is a button with a caret that opens the document menu. I followed the mockup; `onMenu` is that menu. On tablet, History and Download PDF come through `actions`, as the tablet frame shows.
- **Letter panes.** builder.html draws Write / Page / Design for letters. `routes.ts` has `LetterPane = "write" | "design"` and no `letter/[id]/page.tsx`, so the letter chrome has two panes and no tablet page. See follow-ups.
- **Check icon** is `list-checks` (mockup), not M1's `check-circle`.
- **Removed `src/components/pane-bar.tsx`** (M1's placeholder). Only the two layouts used it; `src/shell` replaces it.
- **Root header for `applications/[id]`.** The new nested layout makes the root route `applications/[id]`. The layout hides the root header with `navigation.setOptions({ headerShown: false })`, because I may not edit `app/_layout.tsx`. That file still lists `applications/[id]/[tab]`, so Metro logs `[Layout children]: No route named "applications/[id]/[tab]"`. See follow-ups.
- **No new dependencies.** Uses `expo-network`, `react-native-keyboard-controller`, `react-native-safe-area-context` and the vendored bottom tabs in `expo-router/tabs`.
- **Tokens only.** Mockup sizes that tokens.md states but `tokens.ts` lacks are named constants with their source:
  - the 28×3 iOS marker, the 56×30 Android pill, the 64 dp Android tab height, the 18 pt badge;
  - the tablet title's 320 pt, the workspace context's 270 pt.
