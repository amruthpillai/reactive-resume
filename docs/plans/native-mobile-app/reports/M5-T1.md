## Shared contracts

### `apps/mobile/src/features/applications/queries.ts`

```tsx
applicationsListQueryOptions(server?)
applicationsListQueryKey(server?)
applicationDetailQueryOptions(id, server?)
applicationDetailQueryKey(id, server?)
useApplications()
useApplication(id)
useInvalidateApplications()
useApplicationMutations()
```

- Query option/key functions default to the current server. They extend oRPC's keys with server origin; consumers must use these functions rather than raw `orpc.applications.list` or detail keys. List input is always `{}`; filtering/grouping is local so List, Board, Calendar and Insights share one data source.
- Hooks enable queries only for signed-in sessions; detail also requires a nonempty ID. Hook return values are standard TanStack query results, inferred from M1's router types.
- `useApplicationMutations()` returns standard typed mutation objects: `create`, `update`, `remove`, `bulkUpdate`, `bulkDelete`, `importCsv`. Callers own confirmation, errors and presentation. No optimistic writes or automatic mutation retries are added.
- `useInvalidateApplications()` returns an async invalidator for all `orpc.applications.key()` descendants (list/detail/stats/tags) and `orpc.documents.list.key()`. Mutations invalidate on settlement, including a lost reply. Invalidation is scheduled without holding the save UI open for refetch.
- Server isolation supplements the auth owner's required query-cache clearing on sign-out/server/account switches, especially another account on the same server. No access-token or identity contract was changed.

### `apps/mobile/src/features/applications/stages.ts`

- `PIPELINE`, `LIST_ORDER`, `CLOSED_REASONS` retain the web meanings/order.
- `getStageLabel(status)`, `getClosedReasonLabel(reason)`, `getNextStage(status)` use shared schema types and translated labels.
- `STAGE_COLORS` maps each stage to its named mobile color token. `getStageColor(status, colors)` resolves that token using `useTheme().colors`; no CSS colors or raw hex enter feature code.

Other reusable feature exports:

- `types.ts`: `Application = RouterOutput["applications"]["list"][number]`.
- `list.ts`: `filterApplications`, `groupApplications`, `visibleSelection`, `ApplicationSort`, `ApplicationFilters`. Grouping returns `{ status, data }[]`, does not mutate input and breaks sort ties by ID. Next-step sort uses the earliest current/upcoming interview ahead of follow-up, matching web semantics.
- `next-step.ts`: ported next-step derivation and localized presentation for future list/detail consumers.
- `csv.ts`: web-compatible CSV parsing, mapping, export/range selection plus `parseDateOnly` for form validation.
