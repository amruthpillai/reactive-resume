# M8-T1: accessibility, RTL, tablet, keyboard

Branch `mobile/M8-T1`, base `mobile/native-app` at `6e77416a9`. Static audit only, as instructed. No native build, simulator, emulator or screen-reader session was run. The coordinator's device pass on the shared dev clients still needs to cover VoiceOver/TalkBack, Dynamic Type at 200%, Arabic RTL, Reduce Motion, the tablet frames, and the new native module.

## What was audited

- **Labels and roles.** A script listed every `Pressable`, `Touchable*` and `GestureDetector` under `app/` and `src/` that lacks an explicit role or label.
  - Every hit with a role but no `accessibilityLabel` has visible `Text` children, and React Native takes the label from those.
  - The hits with neither are backdrops (`accessible={false}`) or gesture wrappers around controls that are already labelled: board cards (the card keeps **Move to…**), the page pinch area and the Layout drag handle.
  - `IconButton` and `Button` require a label by type.
  - `Icon` (Phosphor SVG) is not an accessibility element, so decorative icons are already hidden.
  - Text links (`markdown`, `messages`, `resume-reflow`) have `link` roles.
  - One wrong state was found and fixed: the colour swatches.
- **Dynamic Type.**
  - Grepped every `height:` and `maxHeight:` in `app/` and `src/`. In the core flow (sign-in, Documents, Write, Page, Share), the fixed heights are on icon wells, swatches, avatars, page images and `IconButton`s, not on text.
  - The `Button`, `ListRow`, `TextField`, `TopBar` and tab-bar cells use `minHeight`.
  - Only `micro` (tab labels, badges) caps its scale (1.6), as tokens.md specifies.
  - Two text containers outside the core flow had fixed heights; both are fixed. One page miniature now opts out of text scaling.
- **RTL.**
  - Grepped every `left`/`right`/`margin*`/`padding*`/`border*Left|Right`, `textAlign`, `translateX`, `scaleX` and `row-reverse`.
  - The remaining physical `left`/`right` values are correct: positions on the PDF page (Page, Check pins), the board drag overlay (window coordinates), symmetric `left: 0, right: 0` pairs, and Forme page margins.
  - `Icon` mirrors `arrow-left/right`, `caret-left/right` and `arrow-u-up-left/right` through `I18nManager.isRTL`. Every directional icon in the app goes through `Icon`, including those inside `Button`, `IconButton` and `ListRow`.
  - Rows use `flexDirection: "row"`, which React Native mirrors.
  - The Design pane slide, the Slider, the insights bars, the swipe actions and the Check pin rows already branch on `isRTL`.
- **Reduced motion.**
  - Grepped every `Animated`, `withTiming`, `entering`/`exiting`/`layout`, `scrollTo` and image `transition`.
  - The `src/ui` primitives use `useReducedMotion`.
  - The Reanimated layout animations in Design and Check default to `ReduceMotion.System`.
  - The board and Check scrolls honour the flag, and the Check score ring reads `AccessibilityInfo` itself.
  - One raw duration was moved to the motion token.
- **Tablet and hardware keyboard.** The three coordinator items and the iPad shortcuts, below.

## Key commands: contract and decisions

- **Why ⌘1/⌘2/⌘3 and not bare digits.** The brief says "1/2/3". Bare digits would collide with typing numbers into Write fields (dates, GPA, phone numbers). ⌘-digit is the iPadOS convention for switching modes.
- **iOS (`ios/KeyCommandsModule.swift`).**
  - `UIKeyCommand`s with `title`, so they show in the ⌘-hold overlay, are added to the key window's root view controller. Presented modals and form sheets keep it in the responder chain.
  - The action is an `@objc` extension method on `UIViewController`. It forwards the command id to the module through `NotificationCenter`, and the module calls `sendEvent`.
  - ⌘Z / ⇧⌘Z while a `UITextInput` is the first responder (found with the `sendAction(to: nil)` trick) call that field's own `undoManager` instead. So ⌘Z in the rename sheet or the assistant composer never undoes the resume.
- **Android (`KeyCommandsModule.kt`).**
  - The activity's `Window.Callback` is wrapped once (Kotlin `by` delegation), and wrapped again on `OnActivityEntersForeground` for a recreated activity.
  - On key-down with Ctrl or Meta, the base character is matched; the event is consumed and emitted.
  - Ctrl+Z / Ctrl+Shift+Z pass through while an `EditText` is focused, and `TextView` handles its own undo.
  - Shortcuts with nothing registered pass through.
- **JS (`modules/key-commands/index.ts`).** `keyCommands` is `null` when the module is not compiled into the client.
- **Checked here:** `swiftc -parse` on the Swift file. Nothing else was compiled. **The coordinator compiles both platforms in the device pass.**
- **Expected test path on iPad:**
  1. Hold ⌘ in the builder and see Write/Design/Check, Undo, Redo, Print, Search and New.
  2. Press ⌘2 to see Design.
  3. Edit a field, blur it, press ⌘Z, and see it revert.
  4. Press ⌘Z inside a focused field and see only the typing revert.
  5. Press ⌘P to open the print sheet.

`app/_layout.tsx` is unchanged. Nothing needed it: shortcuts register from the tab shell, the builder layout and the chrome.
