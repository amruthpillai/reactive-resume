# M7-T3: Deep links

Status: succeeded. Branch: `mobile/M7-T3`. Base: `d030394d7a1943e0e591e5f21930923d369ee97d`. Local commits only; no push.

## Delivered

- `app/+native-intent.tsx` delegates cold and warm system URLs to `src/linking/open.ts`.
- `src/linking/parse.ts` maps HTTPS `/$username/$slug` to `routes.publicResume`, `/builder/:id` to Write (or the allowlisted `mode`), and known builder panes, entry, Share, History and Assistant paths to their route helpers. Web `/builder/letter/:id` maps to the letter editor. Private-scheme and relative native links also support `/r/:username/:slug` and retain the current server.
- `/auth/native-callback` is returned verbatim, including its query/fragment, for HTTPS, relative paths and the `me.rxresu:` fallback. It bypasses the pending-link queue synchronously, so an OAuth response cannot wait behind the sign-in it completes. No callback query is decoded, displayed, logged or used as an app target.
- A link on another HTTPS origin asks to switch, naming both origins. Only `session.signIn(targetOrigin)` can switch; cancellation or failure keeps the old session. Even an official rxresu.me link asks before leaving a self-hosted session. No old bearer token is read for a foreign-host link.
- Same-server links continue immediately with a usable session token. Signed-out/expired users get a sign-in prompt, then the original target after successful sign-in. Failure offers retry with that target retained. Native intents execute outside React; the handler uses M1's `getAccessToken`/`getServer` instead of calling `useSession` outside a component. No newer session exports are required.
- Cold starts restore the session before checking the server; warm links never restore it. Concurrent links serialize; callbacks never serialize behind them. A server change during token retrieval prevents navigation to the wrong server's document.
- The parser rejects unsupported schemes, credentials, malformed escapes, empty segments, literal/encoded traversal, encoded slash/backslash/control characters, double encoding, reserved web/API prefixes and unknown builder children. Arbitrary query parameters and fragments are dropped; assistant auto-send instructions are not forwarded.
- Android's existing verified callback and builder rules now also include `pathPattern: "/.*/.*"` for public resumes. Existing iOS `applinks:rxresu.me` and `webcredentials:rxresu.me` were already correct and remain intact. App identity stays `me.rxresu`.

## Limits / follow-ups

- No native dev clients, simulator/emulator boots or screenshots, as instructed. No device/system-browser OAuth or live OS link verification was run. Current base still has M1 auth stubs; end-to-end sign-in needs the coordinator's M3-T1 integration. Public screen content comes from M7-T2 at integration.
- Only rxresu.me is statically associated. Foreign HTTPS origins are handled safely when delivered to the app; arbitrary self-hosted domains do not automatically acquire Universal/App Link verification. Live official-domain verification needs the SVa association endpoints configured with the release app IDs/certificate fingerprints.
- Android's simple-glob includes deeper paths and reserved prefixes; native-intent rejects those instead of navigating to web/API screens. Unlike AASA, this compatible intent filter cannot express negative path exclusions.
- Web query parameters other than the allowlisted editor `mode` are not forwarded. New translations are left to the coordinator's wave extraction. No background processes remain.
