## Final behavior after review

- `app/+native-intent.tsx` delegates cold/warm URLs to `src/linking/open.ts`.
- HTTPS app targets are accepted only when their normalized origin is exactly `https://rxresu.me` or exactly the current session origin. Explicit Android ACTION_VIEW intents confer no trust. Arbitrary hosts, suffix/encoded-dot spoofs and unexpected ports cannot trigger a switch-server dialog or `signIn`.
- `parseDeepLink(input, currentServer)` maps public resumes to `/r/:username/:slug`, builder paths to known route helpers, web editor `mode` to its native pane, and web letter-builder paths to the letter editor. Native scheme/relative targets retain the current server. No auth/query/assistant auto-send parameters are forwarded.
- OAuth callback passthrough is restricted to the official HTTPS origin, `me.rxresu:` and relative paths. Even the current self-hosted server's `/auth/native-callback` is rejected. Accepted callbacks return the original URL synchronously, unchanged, bypassing any pending sign-in queue.
- Plain `me.rxresu:///` and `/` return `/` without restoring or prompting. Other rejected/cancelled cold intents also fall back to `/`; warm intents leave the current route intact.
- Rejected HTTPS links reopen using `WebBrowser.openBrowserAsync` (Safari view/Custom Tab), including reserved web/API paths, hostile hosts, foreign callbacks and malformed URL paths. This avoids redispatching an App Link back into the app through `Linking.openURL`. Browser-open failure is caught without logging private query content.
- Same-server links continue with a usable token. Signed-out/expired users sign in, then continue to the original target. A link to the official origin while using a self-hosted server offers a switch; only `session.signIn` changes the server, atomically with its tokens. Cancel/failure preserves the old session; failure offers retry. The allowlist is rechecked after cold restoration, after queuing and before every sign-in attempt.
- The parser rejects unsupported schemes, credentials, malformed escapes, empty segments, literal/encoded traversal, encoded separators/control characters, double encoding, reserved prefixes and unknown builder children. A changed server after token retrieval sends the HTTPS target to the browser instead of opening a document on the wrong server.
- Android verified links now include **only** `/builder/` and `/auth/native-callback` on `rxresu.me`. The broad public-resume pattern was removed per coordinator decision. iOS keeps `applinks:rxresu.me` and `webcredentials:rxresu.me`; identity remains `me.rxresu`.

Native intents run outside React and before the cold-start navigator. System dialogs use Lingui macros; only M1 session exports are consumed. No dependencies, root layout, auth/session, route-contract, lockfile, catalog or ledger edits. Initial blocker commit `c9b646d24` was superseded by explicit coordinator direction to implement against M1 without merging M3-T1/M7-T2; their sources/reports were read via `git show`.

## Coordinator-owned startup race (review 3c)

**Still requires a session-owner fix before shipping.** `app/_layout.tsx` independently calls `restoreSession()` at mount, while the native-intent handler calls it before a cold-link continuation. `src/auth/session.ts` does not expose a shared readiness barrier and its restoration is neither single-flight nor protected against a newer sign-in. The M3-T1 branch also restores directly outside its session-transition queue.

Credible ordering: the root restore reads old server A, then stalls reading A's tokens; the intent's restore completes; the user follows the link and `signIn(B)` commits B; the delayed root restore assigns A's tokens/server back into memory. Rechecking `getServer()` before navigation can avoid a wrong document but cannot undo that stale session write.

Fix belongs in `src/auth/session.ts` (or coordinated root startup), outside M7-T3 Ownership: share one startup restoration promise across both callers, and serialize/guard the entire restore against later session transitions so stale reads cannot mutate tokens/account scope/server after a successful sign-in. Cover a delayed old-server read completing after a new sign-in. Do not infer that linking's own promise queue protects an independent root restore. No ownership-crossing workaround was added; this is a documented follow-up under the coordinator's explicit review instruction.
