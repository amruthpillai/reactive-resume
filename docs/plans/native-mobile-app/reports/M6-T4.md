## Shared contract

Import from `@/features/ai/providers`:

```tsx
const {
  hasAIProvider, isLoading, isUnavailable, error, retry,
  providers, usableProviders, defaultProvider,
} = useHasAIProvider();

<AIProviderSetupSheet
  open={setupOpen}
  onClose={() => setSetupOpen(false)}
  onReady={() => { /* optional: resume the caller's workflow */ }}
/>
```

- `hasAIProvider` is boolean. `providers` and `usableProviders` are arrays of the inferred API response type; `defaultProvider` is the first runnable provider in server order or `null`.
- Pending/error/signed-out lookups never establish readiness from stale cached data. `isLoading` is true only while a signed-in lookup is pending; it is false when the query is disabled, including signed-out sessions. `isUnavailable` remains true until readiness can be established. Callers should use `isLoading` for spinners, show retry on errors, and follow the sign-in flow for signed-out sessions. `retry()` starts a refetch.
- `AIProviderSetupSheet` props: `open: boolean`, `onClose: () => void`, optional `onReady: () => void`. Opening keeps the caller mounted. A successful test refreshes provider queries, calls `onReady`, then calls `onClose`. Failed test/save stays in the sheet with fields retained. Closing unmounts the form and discards typed keys. Managed/unavailable servers show explanatory state instead of an editable form.
- Query keys extend the existing oRPC provider key with server origin. Mutations invalidate `orpc.aiProviders.list.key()` so both settings and consumers refresh. Standard auth-session query-cache clearing remains the session owner's responsibility, including switching accounts on the same server.
- New routes: `/settings/ai` (existing entry), `/settings/ai-providers`, `/settings/ai-web-access`, `/settings/ai-mcp`. No M1 route-builder edits required.
