## Review fixes (Codex `895bc4ca`, 6 blockers)

Merged `mobile/native-app` first (M2-T2's shell, `useResumeDraftOwner` in the builder layout, `useIsTablet()`); clean.

1. **Draft race:** `useDesignDraft` is subscribe-only (`useResumeStore()`); it never calls `open`. Design also no longer mounts `ResumeConflictSheet` (the layout does).
2. **Stepper undo:** every Stepper caller (typography size/line height, Advanced page margins/spacing, sidebar width) writes with `discrete = true`, so each −/+ tap and each committed typed value is its own undo step. Slider drags and hex/CSS typing still coalesce. `writeTo` moved to a pure `write.ts` so the scenario drives the real `createDraftStore`.
3. **Colour input:** `parseColorInput` accepts hex, or `rgb(a)` with channels 0–255 and alpha 0–1, and returns a canonical `rgba(r, g, b, a)`; `rgba(999, 0, 0, 1)` and alpha > 1 are rejected (field shows its error and nothing is saved).
4. **Contrast with alpha:** `contrastOver(color, background)` lays the background over white paper and the colour over the background (WCAG luminance), so `rgba(0, 0, 0, 0.01)` reads ≈ 1:1 and triggers the warning. A typed hex is opaque; otherwise the saved primary (with its alpha) is measured against the saved background.
5. **Lingui:** pairing names and accent names are `msg` descriptors, translated with `i18n._` at render.
6. **Tablet preview:** the held template lives in a small zustand store in `src/features/design/draft.ts` (`usePreviewTemplate`, `setPreviewTemplate`, cleared when Design unmounts). `usePreviewedDraft(draft)` swaps it into the data (memoised, read-only so Fit can't write the preview) and `TemplatePreviewCaption` draws "Previewing X · tap to apply" (tap applies through `applyTemplate`). Both the phone Design half-page and the tablet page use them. Ownership extension (approved): `app/builder/[id]/page.tsx` gains the two imports, one `usePreviewedDraft` line and the caption. On phone, Page and Design are never mounted together, so the Page pane is unaffected.

Also: the local 700 pt check is now `useIsTablet()`.

New scenarios (15–17): out-of-range colour channels and alpha rejected, canonical rgba; alpha-aware contrast (0.01-alpha black ≈ 1:1, background counts, transparent background = white); two stepper taps undo one at a time while a four-move slider drag undoes in one step, against the real draft store.

## Final review fix (1 blocker)

`usePreviewedDraft` locked the page but kept the live `undo`, so Fit's Undo on the tablet page could still change the saved draft during a preview. Now, while a template is held, `readOnlyDraft` (`src/features/design/write.ts`) replaces every function the draft exposes (`update`, `undo`, `redo`, `flush`, …) with a no-op, so neither Fit nor its toolbar Undo can write; data stays the previewed copy and `locked` stays true. Scenario 18 (real draft store): after a Fit-style step, the preview draft's `undo`/`redo`/`update` leave the saved data unchanged, and the real Undo still works once the preview ends.
