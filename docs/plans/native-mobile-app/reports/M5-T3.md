# M5-T3: Applications board, calendar and insights

Status: succeeded. Branch: `mobile/M5-T3`. Base: `mobile/native-app` @ `a17f4bcb9`. Local commits only; no push.

## Delivered

- **View switch.** `ApplicationsViewFrame` puts the mockup's List / Board / Calendar / Insights segmented control above each Applications view. Each view is a sibling route under `app/(tabs)/applications/` (`index`, `board`, `calendar`, `insights`); switching uses `router.replace` with `animation: "none"`, so the views swap in place with no back stack. `index.tsx` (M5-T1's) now wraps `ApplicationsListScreen` in the frame: the one-file ownership extension the launch prompt allowed. `list-screen.tsx` is untouched.
- **Board** (`board-screen.tsx`): one column per stage (Saved → Offer, plus Closed behind a "Show closed" switch, as web), with stage dot, count, and 50 cards per column then "Show N more" (web `COLUMN_PAGE_SIZE`). Cards show role, company · location and the next step (M5-T1 `describeNextStep`), open the application detail, and have a visible **Move to…** button plus a screen-reader "Move to…" action (mockup `app-move`).
  - **Drag:** long press (400 ms) lifts the card into an overlay that follows the finger (raised `e2`, 1.02 scale unless Reduce Motion), dims the source card, and highlights the column under the finger (`accentSoft` + `accent` border). Holding near the board's edge scrolls one column every 500 ms, so phone drags reach off-screen stages. Selection haptic on lift, light impact on drop.
  - **Drop rules** match the detail stepper (M5-T2): Closed opens M5-T2's `CloseSheet` (reason); Saved → Applied opens `MarkAppliedSheet` (what was sent); any other move calls `useApplicationMutations().update` (M5-T1's optimistic update with rollback) and toasts "Moved to {stage}" or the error. Like web, a pending-move override keeps the card in its new column until the optimistic list update lands, so it doesn't blink back.
  - **Layout:** phone columns are 268 pt (narrower on small phones so the next column peeks) with snap paging; tablet columns are 250 pt without snapping (mockup `.column`). Tablet means ≥ 700 pt wide, M2-T2's `useIsTablet()` rule (local copy until M2-T2 merges).
- **Calendar** (`calendar-screen.tsx`): month grid (6 weeks), previous / next / This month, interview count for the month, and a legend. Days are dates on the **user's clock** (profile timezone through M5-T2's `useUserTime`, falling back to the device's), so an interview sits on the same day the detail screen shows. Shows interviews and follow-ups of open applications; closed applications stay off it.
  - Phone cells show up to three dots (interview `accent`, follow-up `warn`); tablet cells show "16:00 Company" lines and "+N more". Event days use `accentSoft`, today an `accent` disc, the selected day `selectedFill`. Each cell's accessible label reads the full date and "1 interview, 1 follow-up".
  - Tapping a day shows that day's agenda; below it, **Coming up** lists interviews that haven't ended and follow-ups from today on, grouped by day (Today / Tomorrow / date). Tablet puts the agenda in a 400 pt column beside the month (web layout); phone stacks it.
  - An interview card shows the time range on the user's clock, "07:00 in America/Los_Angeles" when the interview has its own zone, type · length · role, and location; tap edits it in M5-T2's `InterviewSheet`. A follow-up card taps into M5-T2's `FollowUpSheet`. Both have View application.
  - **Schedule interview** picks an open application (mockup `app-interview-new`), then opens `InterviewSheet` for it. The empty agenda is the mockup's "Nothing scheduled yet" state with the same action.
  - First day of the week comes from `Intl.Locale#getWeekInfo` where the engine has it, else Monday (mockup).
- **Insights** (`insights-screen.tsx`), every chart hand-drawn with `react-native-svg`:
  - "How far applications get": funnel rows per stage reached (closed applications counted by furthest stage), stage colours from tokens, bars grow from the start edge (mirrored in RTL).
  - "heard back" and "median to first reply" tiles; "Tailored vs. base resume" (documents made for the application through Copy for a job, via M5-T2's server-scoped `useDocuments`).
  - "Applications over time": sent per week for the last 8 weeks, weeks on the user's clock starting on the locale's week start. "Where applications come from": per-source bars.
  - "Where your applications went": the web pipeline-flow picture (bars and gradient bands) in token colours, with the stage-to-stage totals as text for screen readers (mockup `app-pipeline`). **Share PNG** renders the SVG with `Svg#toDataURL` at 2×, writes `pipeline-flow-<ts>.png` to the cache and opens the share sheet; the previous picture is swept on the next share.
  - **Export CSV** opens M5-T1's CSV sheet. Empty state before anything is sent, as web.
  - All figures come from the shared applications list (it holds every application), so there is no `applications.stats` query; the server's stats are the same `GROUP BY` over the same rows.
- Every user-facing string uses Lingui macros; no extraction run. Colours, type, spacing and radii come from tokens. No new dependencies; no manifest, lockfile, M1 contract, `routes.ts`, shared UI or other task's files changed. Identity stays `me.rxresu`.

The scenarios import the shipped `calendar.ts` and `insights.ts` directly (Node 24 type stripping; both import `zonedParts` with a `.ts` extension so Node can load them):

- An interview at 22:30 UTC lands on 20 Oct in Berlin and Tokyo and 19 Oct in Los Angeles; the Berlin DST fallback night (25/26 Oct 2026) buckets on the correct local day.
- Follow-ups: web's UTC-midnight dates and the app's 09:00-local instants both keep their calendar date in Los Angeles, Auckland and Tokyo.
- Events: closed applications excluded, end from duration, sort by day then time; upcoming keeps a running interview and today's follow-up and drops a finished interview.
- Month grid: 42 days from the week start (Mon 28 Sep / Sun 27 Sep for Oct 2026), and March 2027 has no skipped or repeated day across the European clock change; month shifting across years.
- Week start from Intl (en-US Sunday, en-GB / de-DE Monday).
- Outcomes (web parity): funnel by furthest stage including closed ones, heard back (screening, interview, or "not selected" rejection), median days to reply, tailored vs base only for sent applications with a resume.
- Timeline: a send at 23:30 UTC on a Sunday falls in Berlin's next week but Los Angeles's current one; Sunday-start weeks move it again; saved-only and out-of-window applications don't count.
- Pipeline conversions among active applications (web `computeInsights`), and per-source counts sorted with empty sources dropped (server `stats` parity).

Mutation check: replacing the follow-up UTC-midnight rule with plain zoned bucketing, or bucketing weeks by UTC date instead of the user's clock, fails the matching scenarios (10/12); restored afterwards.

Test-audit gate: no Vitest suite added. The harness guards client-only maths that a regression would break silently (an interview or follow-up shown on the wrong day for users west or east of UTC, wrong reply rates or week buckets). Web/server tests can't reach this mobile code. It adds no test-only production seams.
