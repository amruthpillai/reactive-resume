## Decisions

### Bottom sheets: `@gorhom/bottom-sheet` (5.2.14)

- One JavaScript API on both platforms, built on Reanimated and Gesture Handler, which the app installs anyway. It adds no native code.
- Styling is fully ours, so the token rules (`raised`, `r3xl` / `rSheetA`, grabber, `scrimSheet`) apply directly. It has detents (`snapPoints`), content sizing, keyboard handling and scrollables.
- Expo UI (`@expo/ui`) sheets are separate SwiftUI and Jetpack Compose component trees, still early, and would need two implementations per sheet.
- Route-level sheets can also use expo-router's native `presentation: "formSheet"` at no cost.
- Peer range `react-native-reanimated >=4.0.0-`; it works with Reanimated 4.7.1 and Gesture Handler 3.3 (the legacy `Gesture` API is still exported). `Sheet` in `src/ui/overlays.tsx` uses it; the provider is in `app/_layout.tsx`.

### Reorderable lists: `react-native-reorderable-list` (0.18.1)

- Named in README §1.4. A FlatList with drag-to-reorder on Reanimated, with nested-scroll support, which fits the outline, entries and pages.
- It reorders inside one list only. Moving between lists (board stages, main ↔ sidebar in layout pages) needs Gesture Handler + Reanimated directly, or a "Move to…" action. No library covers that well enough to add a second one now.
- `SortableList` in `src/ui/sortable.tsx` wraps it.

### Boundaries (SV6)

- Root `turbo.json`: `app:mobile` denies `app:server`, `app:web`, `runtime:server`, `runtime:browser`. `runtime:native` denies `app:web`, `app:server`, `runtime:server`, `runtime:browser`.
- **The brief's premise did not hold.** Web has no type-only exception: `app:web` has no tag rule, so web may depend on server packages. Turbo tag rules check `dependencies` and `devDependencies` transitively, and have no exceptions. A `devDependency` on `@reactive-resume/api` fails `runtime:server`.
- What I did: `@reactive-resume/api` is a **`peerDependency`** (`workspace:*`) of `mobile`. pnpm links it (auto-install-peers), TypeScript resolves the router type, and turbo's tag rules ignore peers.
  - The one import has `// @boundaries-ignore type-only import of the server router` for the file-level check.
  - `apps/mobile/.oxlintrc.json` extends the root config and adds `no-restricted-imports` with `allowTypeImports: true` for `@reactive-resume/api*`, so a value import fails lint.
  - Any real runtime dependency on a server package still fails `turbo boundaries`.
- If the coordinator prefers dropping `runtime:server` from the deny list instead, that is a one-line change; see QUESTIONS.

## Contracts (for later waves)

- `src/api/client.ts`:
  - `client`, `streamClient`, `orpc`, `RouterInput`/`RouterOutput` (`RouterClient<typeof router>` like web).
  - `rest(path, init)` sends the bearer token to `${server}/api/openapi${path}`.
  - Requests use `expo/fetch`. The error interceptor logs only the error name, never data.
- `src/auth/session.ts`:
  - API: `useSession()` → `{ status: "loading" | "signed-out" | "signed-in" | "expired", server }`, `getServer()`, `restoreSession()`, `saveTokens()`, `signIn(server): Promise<boolean>`, `signOut()`, `getAccessToken()`.
  - Tokens are held only in SecureStore. The S3 rules (resource on all three requests, single-flight refresh, DCR caching, callback, `preferUniversalLinks`) are in the module JSDoc.
  - `getAccessToken()` already shares one in-flight refresh.
  - Switching servers is atomic (review fix): `signIn(server)` changes nothing until it has tokens, then the internal `switchSession` writes them, writes the server, and swaps both in memory at once. A failed or cancelled sign-in leaves the current server and tokens untouched. `saveTokens` (refresh) drops its result if the server changed meanwhile.
  - Token keys are `tokens.<hex of the origin's UTF-8>`: collision-free within SecureStore's `[A-Za-z0-9._-]` key set (review fix).
  - `authorize` (inside `signIn`) and the refresh itself throw "not implemented (M3-T1)". `signOut` deletes tokens; revocation is M3-T1.
- `src/ui/index.ts`: Button, IconButton, TextField, TextArea, SelectSheet, Switch, Segmented, Chip, ChipInput, ListRow, Card, Sheet, ConfirmDialog, Toast (`showToast`/`dismissToast`/`Toaster`), EmptyState, Banner, Avatar, Skeleton, SortableList, plus Icon, Text, Screen, `useTheme`, `setThemePreference`/`useThemePreference`. Each is a plain working stub with its final props type.
- `src/ui/tokens.ts`: tokens.md §1–§6 verbatim (`colors.light/dark`, `fonts`, `type`, `space`, `size`, `radius`, `shadows`, `motion`, `pageThumb`).
- `src/routes.ts`: typed href builders for every route (`routes.builder(id, pane)`, `routes.entry(id, section, item)`, `routes.application(id, tab)`, …).
- `src/draft/types.ts`:
  - `DraftStore<TDocument, TData>` with `document`, `data`, `status`, `locked`, `conflict`, `canUndo`/`canRedo`, and the actions `open`, `close`, `update` (with coalesce options), `updateDocument`, `undo`, `redo`, `retry`, `resolveConflict`, `flush`.
  - Also `ResumeDraftStore`, `LetterDraftStore`, `SaveStatus` and `ConflictChoice`.
- `src/preview/types.ts`: `RenderRequest` (with optional `renderOptions`, for example `includeCoverLetterHeader` for letters), `RenderedPage`, `RenderedPages` (page PNG URIs, page map, lost characters, PDF bytes). `ResumeRenderOptions` is read type-only off `@reactive-resume/pdf/document`'s `ResumeDocument` props, because no public pdf entry exports it by name; switch to the named type when M1-T2's `./native` exports it.

- `headerLeft` was passed as a component reference, which broke the `useLingui` context.
