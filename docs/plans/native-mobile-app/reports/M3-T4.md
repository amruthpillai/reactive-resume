## Delivered

- `@reactive-resume/pdf/native` now exports the named `ResumeRenderOptions` type and `preloadResumePdf(data): Promise<void>`. The preload warms the configured font reader and rejects missing fonts. `RenderResumePdfOptions.readImage` supplies a per-render native image reader. No web/server renderer changes.
- `modules/pdf-pages` is an autolinked local Expo module. `open(pdf)` returns an opaque document id and page dimensions; `rasterize(id, zeroBasedPages, pixelsPerPoint)` writes PNGs and returns their file URIs; `close(id)` releases the document and files. Swift uses PDFKit, Kotlin uses `android.graphics.pdf.PdfRenderer`, both on dedicated serial queues. Invalid indices/scales are rejected. Requested scale is bounded to 0.1–6; each page independently lowers its raster scale to stay within 25 million pixels, preserving its PDF-point dimensions.
- `src/preview/resources.ts` configures a persistent `expo-file-system` font reader, with SHA-256 URL keys and atomic writes under `Paths.cache/pdf-fonts-v1`, capped at 200,000,000 bytes with oldest-write-first eviction. Cache reads and network bytes must have a recognized font signature; corrupt cached files are removed and downloaded again. Serialized disk operations preserve the cap with concurrent font downloads. The former Documents cache is removed on configuration, best effort. Disk read/write failures fall back to `downloadFont`. Images stream through `expo/fetch`, reject above 12,000,000 bytes and cancel their readers. Data URIs decode locally, including percent-encoded binary bytes. Relative URLs resolve against `getServer()` before fetching. No unbounded image `arrayBuffer()` fallback.
- The scheduler serializes native work, coalesces pending work and invalidates old results immediately when a newer request arrives, even during debounce. Delays match web: 100 ms normally, 250 ms with field focus. Unmounted viewers discard results and release their documents. Zoom/scroll reuse PDF bytes; only requested visible pages are rasterized. The prior document survives the next image transition.
- Page body includes an `expo-image` crossfade, reduced-motion handling, 60–150% zoom controls, Fit, pinch and double-tap, horizontal pan and vertical page scrolling. Measured row positions drive visibility. Page-map taps snap to nearby header/item regions, show selection, and route Edit entry through `routes.entry`. Accessibility actions provide an alternative to coordinate taps.
- Overflow captions expose Fit to one/the authored pages. Fit measures a private candidate using the real engine, applies density, margins, then half-point size changes with a 9 pt floor, and commits once through `DraftStore.update` for one undo step. A newer edit cancels application of the candidate. Lost-character warnings include unnamed engine text loss, plus a generic retry state for failed renders.
- Parity tooling under `apps/mobile/scripts/parity` compares the real server adapter in Node with the real native adapter, subsetter and engine on device. PDF.js compares page count and exact concatenated extracted text on every page. A free-form case explicitly checks a measured second pass; the original Bronzor case exercises a repair pass. The device runner is development-only and single-flight.

## Wave contracts and integration

- `usePreview(data: ResumeData | null, template?: Template, options?)` lives at `src/preview/usePreview.ts`. Returns `{ result, rendering, error, retry, displayScale }`. `result` preserves M1's `RenderedPages` shape; additive `hasTextLoss` covers warnings without named characters. Options support `focused`, `pages`, physical raster `scale`, `renderOptions`, and a viewport.
- `ResumePage({ id, draft, focused? })` consumes `Pick<ResumeDraftStore, "data" | "update" | "locked" | "undo">`.
- `PageScreen` now uses M3-T3's `useResumeDraft(id)` lifecycle and real `data`, `update`, `locked` and `undo` actions. It hides a previous document while a new id loads, exposes load retry/session states, and mounts `ResumeConflictSheet`. The production sample binding and sample banner are removed. There is one draft-owner hook in the currently merged builder; do not add a second owner when integrating further panes.
- Page passes the existing draft layer's `nativeEnvironment.focused()` probe (native TextInput state or keyboard visibility) to the preview. The merged Write route is still a stub; future enriched-HTML/tablet panels can pass their explicit `focused` state through the existing `ResumePage`/`usePreview` option. The development field uses M3-T3's shared `resumeFieldFocus` handlers. Both hardware-keyboard iOS input and Android soft-keyboard input were exercised. M2 shell/chrome remains outside this task's ownership.
- Configure `configurePreviewResources()` before a standalone `preloadResumePdf` call. The pipeline configures it itself.
