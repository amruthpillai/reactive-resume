# S2 report: the packages/pdf pipeline on Hermes

Branch `mobile/S2`, base `3d3d5b36f`. Spike app: `apps/spike-s2/` (throwaway, not for merge). Date: 2026-10-17.

## Result

The TypeScript half of resume rendering runs on Hermes without changes and without polyfills. That half is the template, then the reconciler, then the host tree, then `toFormeDocument`. For `sample.ts` × `azurill`, `pikachu` and `onyx`, the Forme document JSON from Hermes deep-equals the JSON from Node:

- on iOS (simulator, Release build);
- on Android (emulator, release build);
- in two launches each.

## React strategy: one copy, nothing to isolate

- Expo SDK 58 pins `react@19.3.0`, which is what the workspace catalog (`^19.3.0`) already resolves to.
- `react-reconciler@0.34.0` peers on `react ^19.3.0`.
- After `pnpm install` there is one `react@19.3.0`, one `react-reconciler@0.34.0_react@19.3.0` and one `scheduler@0.28.0` in `node_modules/.pnpm`.
- Metro follows pnpm symlinks to real paths, so the app and `packages/pdf` share one module instance.
- **Evidence:** the reconciler renders all three templates on Hermes, and the resulting JSON deep-equals Node's. A second React copy would have broken hooks and context inside the templates, which happens with "Invalid hook call" or a missing context value.

**Decision for M1:** use the catalog `react` in `apps/mobile`, and keep it on the same minor as Expo's pin. When Expo moves React, the catalog moves with it.

The fallback in §8 (`packages/pdf` with a peer-dependency React) is not needed.

### What was compared

- `src/pipeline.ts` is one module, run by both runtimes: through `tsx` on Node (`pnpm node-capture`) and inside the app on Hermes.
- It calls `renderResume` (via the proposed `renderResumePdf` adapter) with a stub engine. The stub's `renderSerializedDocWithLayout` records the document and returns `{ pdf: empty, layout: { pages: [] }, warnings: [] }`.
- The stub layout has no pages, so the repair passes find nothing. Only the first-pass document is produced: 1 document per template. These three templates have no free-form page, so no measured second pass runs. **This compares the first pass only.** Repair-pass parity needs the real engine (S1) and is covered by the M3 renderer-parity check.
- Font bytes are serialised as `{ bytes, fnv1a }`, so the JSON stays small while still catching different bytes. Everything else is compared verbatim: styles, numbers, text, and the picture as a base64 data URI.
- Fonts and the picture came over the network on both sides, as on the browser path:
  - Fonts: IBM Plex Serif and Fira Sans Condensed, plus fallbacks, from `fonts.gstatic.com` through `forme/fonts.ts`.
  - Picture: `https://rxresu.me/photos/sample-picture.jpg`, through `forme/images.ts` → `readImageBytes`. The sample's picture URL is relative to the web origin, so the spike swaps in this absolute URL on both sides.

## Proposed diff for packages/pdf

Full patch: `reports/S2/packages-pdf.patch`. It applies cleanly to `3d3d5b36f` (`git apply --check`). I validated it in a scratch worktree, which I then removed:

- `oxlint --deny-warnings`: clean.
- `oxfmt --check`: clean.
- `tsgo --noEmit` in `packages/pdf`: exit 0.
- `vitest run src/forme/fonts.test.ts src/forme/images-security.integration.test.ts src/browser.test.ts src/forme/font-subset.integration.test.ts`: 4/4 passed.

The patch has three parts:

1. **`package.json`:** add the export `"./native": "./src/native.tsx"`.
2. **`src/native.tsx` (new, about 35 lines):**
   - `renderResumePdf(engine, options) → Promise<Uint8Array>`. It has the same contract as `createResumePdfBlob`, with the engine injected.
   - It re-exports the `FormeEngine` type, plus `configureFontReader` and `downloadFont`.
   - It has no React Native import. `packages/forme-native` supplies `{ renderSerializedDocWithLayout, prepareFont }`, where `prepareFont` wraps its native `subsetFont`.
3. **`src/forme/fonts.ts`:**
   - Split the download out as an exported `downloadFont(src)`.
   - Add `configureFontReader(reader)` so the app can wrap it with a persistent `expo-file-system` cache: `reader = src => fromDisk(src) ?? persist(await downloadFont(src))`.
   - The in-memory cache and WOFF→sfnt conversion stay in the package. Web and server keep calling `downloadFont` through the default reader, so their behaviour is unchanged.

   This mirrors the existing `configureOwnPictureReader` pattern on the server.
4. **`src/forme/images.ts`:** when `response.body?.getReader` is missing, read `arrayBuffer()` and then apply the 12 MB check. Not needed with Expo 58's default fetch. Kept as the portable fix §1.4 asked for.

`AbortSignal.timeout` needs no fix.

The spike's copy is `apps/spike-s2/src/native.tsx`. It is identical except that its imports use the spike-only `pdf-internal/` alias.

## Metro config for M1

Expo 58's `getDefaultConfig` already handles this pnpm monorepo. It watches the workspace root, follows pnpm symlinks, honours package `exports` and package `imports` (`#react-pdf-renderer` resolved with no help), and respects the `react-native` condition. Once `./native` exists, M1 needs no resolver changes:

```js
// apps/mobile/metro.config.js
const { getDefaultConfig } = require("expo/metro-config");

module.exports = getDefaultConfig(__dirname);
```

Import with `import { renderResumePdf, configureFontReader } from "@reactive-resume/pdf/native"`. Never import `@reactive-resume/pdf/browser` from mobile, because it pulls in the `?url` WASM imports.

The spike's extra `resolveRequest` is only for `pdf-internal/*` (until `./native` exists) and the bundle-size toggle. Do not copy it.

Other setup notes:

- **`tsx` on Node:** it applies `jsx: react-jsx` only to files inside the tsconfig's `include`. Scripts that run `packages/pdf` sources from an app need `include` to cover them, or `React is not defined` is thrown.
- **Android release builds:** Homebrew's `openjdk@17` has no `jlink`/`jmods`, and AGP fails with `IllegalArgumentException: …/jdkImage`. Use a full JDK 17 or 21 (here: Gradle's JetBrains JBR 21 in `~/.gradle/jdks`). EAS is unaffected.

## Timings

Release builds, Hermes. Measured as host tree (`renderHostTree`) plus `toFormeDocument`, with fonts, icons and picture warm. Median of 15 runs after 3 warm-up runs (`timeTemplate` in `pipeline.ts`). Each cell shows two app launches.

| Template | Node 24 (M1 Max) | iOS sim (Hermes, M1 Max) | Android emu API 37 (Hermes) |
| -------- | ---------------- | ------------------------ | --------------------------- |
| azurill  | 16.9 ms (10.9 tree + 5.9 convert) | 50.3 / 45.7 ms (≈35 tree + 12 convert) | 92.0 / 49.1 ms |
| pikachu  | 13.8 ms | 46.5 / 44.5 ms | 71.8 / 64.4 ms |
| onyx     | 12.0 ms | 46.4 / 44.2 ms | 92.0 / 64.4 ms |

- Hermes is about 3× slower than Node's JIT here. The tree build is about 75% of the time.
- Android emulator numbers are noisy: two other spikes were building on the same machine.
- The first capture per template on Android, cold, took 2843 / 935 / 1061 ms. That includes the font downloads (first template only), the icon JSON and the picture fetch.
- No physical device was available, so there are no device numbers. A mid-range Android is likely 2–3× slower than the emulator on an M1 Max. That puts the JS half at roughly 100–250 ms per render, inside the 400 ms p50 budget in §7 before Forme layout is added (S1).
- Main lever if needed: `images.ts` refetches the picture on every render (no cache). It does not affect these timings, but it does affect the real preview loop.

## Blockers for on-device native rendering

None found on the TypeScript side. Remaining dependencies and risks:

1. **The S1 native engine** must accept this document JSON. Font `src` arrives as `Uint8Array`, or whatever `prepareFont` returns, and must be passed across the native boundary. Serialising about 1 MB of fonts per render as base64 JSON would cost real time. S1/M1 should pass font bytes separately, as `ArrayBuffer`, through the Expo module.
2. **The repair passes** (list breaks, unplaced blocks, free-form heights) were not exercised. They need a real layout. The M3 parity check covers them.
3. **App-wide polyfills** outside the PDF path: `crypto.getRandomValues` (uuid) and `toSorted`, as above.
4. **Bundle weight:** +1.7 MB gzip for the pipeline. Acceptable. Trimming the icon JSON (load it from an asset or the file system) and `unicode-regex` are the obvious cuts if the G1 budget needs them.

## How to reproduce

```sh
pnpm --filter spike-s2 node-capture      # writes reports/S2/node.json
pnpm --filter spike-s2 host              # :18092, compares each device's POST with node.json
cd apps/spike-s2
npx expo run:ios --configuration Release --device <rr-S2 udid> --port 8092
JAVA_HOME=<full JDK 17/21> npx expo run:android --variant release --device emulator-5557 --port 8092
S2_BARE=1 npx expo export --platform ios   # bundle without the pipeline
```

The app runs the probe and captures on launch, then POSTs to the host:

- iOS posts to `localhost`.
- Android posts to `10.0.2.2`. Release builds allow cleartext through `cleartext-plugin.js`, for the spike only.

The 1 MB capture JSONs are not committed. Re-create them with the commands above.
