# M3-T5: Builder Write

Status: succeeded. Branch `mobile/M3-T5`, based on `mobile/native-app` @ `2f41c9665`. No push.

## Delivered

- **Write pane** (`app/builder/[id]/write.tsx`). It owns the draft through `useResumeDraft(id)`, the same way Page does. It mounts `ResumeConflictSheet` and shows a load/retry banner and a signed-out banner. The content is the outline in Direction B, "Outline first":
  - Banners: Locked, with Unlock, which calls `resume.setLocked` and then refreshes the draft. Imported, which reads an optional `?imported=<source>` route parameter.
  - The Basics card: photo or initials, then name · headline · location. Tapping it opens the Basics screen.
  - The sections in print order, as one `SortableList` from `src/ui`:
    - Page N and Sidebar dividers. Hidden sections are grouped at the end, struck through, and their handle is disabled.
    - Each row has a "to check" badge, an entry count, the eye (hide from page) and ⋯.
    - Open sections list entry cards (Draft / Hidden / To check badges, title and "company · location · dates", ⋯) and "+ Add {type}".
    - Hold ⋮⋮ for 250 ms to drag a section or an entry. A section lands after the section above it, or at the start of the column a divider opens, so a drag can cross the Page and Sidebar dividers. An entry stays in its own section; dropped outside it, it snaps to the nearer end.
    - Section rows also expose VoiceOver/TalkBack "Move up" and "Move down" actions.
  - A blank resume shows the suggestion chips (Experience, Education, Skills, Summary) and "Import it", which opens `routes.new()`.
  - Add section: every section not in use, then Custom section ("What goes in it?") with all 13 types. A new section opens its first draft entry with the first field focused.
- **Section sheet.** It has every web action:
  - Add entry, Sort by date (experience and education), Move up and Move down.
  - Move to…: Page N, Page N · Sidebar (only on pages that are not full-width), or New page.
  - Rename… (web's prompt copy), Icon…, and switches for Show on page, Show heading, Keep on one page and Start on a new page.
  - Columns (1–6, plus "1 column, inline" for Skills) and Keyword layout (Skills).
  - Clear section (built-in) or Delete section (custom only). Both show an Undo toast and do not ask first.
- **Entry options sheet**: Hide from page / Show on page, Duplicate, Move to…, Delete with Undo. Move to… offers sections of the same type on each page, New section on a page, and New page. A custom section emptied by a move is removed, as on web.
- **Entry editor** (`entry/[section]/[item]`, full screen) for all 13 section types:
  - Fields come from the `fields.ts` schema, ported from web's `entries.tsx`.
  - Experience has roles: position, dates and description each, with ↑ ↓ and ×.
  - Keywords split on commas.
  - Level (0 = Hidden, 1–5) and Icon/Icon colour sit behind "More options".
  - A link field has "Show link in title"; https:// is added on blur when it is missing.
  - A draft entry shows the "Appears on the page once it has…" hint.
  - ⋯ in the header opens Entry options.
  - A locked resume opens entries read-only.
- **Basics screen** (`entry/basics/basics`):
  - Photo row, Full name, Headline, Email (with web's validation messages after blur), Phone, Location, and Website (with its label).
  - Custom fields: text, icon picker, link prompt, move up, and remove with Undo; Add field.
- **Picture screen** (`entry/basics/picture`):
  - Upload: `expo-image-picker` library. The crop uses the picture's aspect ratio for Cover; there is no crop for Contain, as on web. The file is checked against the 10 MB limit, then sent as multipart `POST /files` through `rest()`, following the M7-T1 pattern. The returned URL is validated.
  - Delete picture: it confirms first. It calls `storage.deleteFile` only for files on the current server.
  - Other controls: URL, Show picture, Fit, Size, Rotation (disabled, with web's note), Aspect Ratio with Square/Landscape/Portrait presets, Border Radius, Border Color/Width, and Shadow Color/Width.
  - An upload failure keeps the previous photo and offers Retry.
- **Summary screen** (`entry/summary/summary`): rich text with "2–3 sentences reads best" and Improve.
- **Rich text** (`react-native-enriched-html`):
  - The toolbar docks above the keyboard (`KeyboardStickyView`, keyboard-controller). It has Bold, Italic, Underline, Strikethrough, the two list types, Link (prompt; empty removes it), Text style (Paragraph and Heading 1–3), and ✦ Improve. It scrolls sideways; Done stays pinned.
  - A table in the stored HTML makes the field read-only, with web's note.
- **Only edited fields re-serialise** (`rich-text.ts`):
  - The serialisation the editor reports for the stored value becomes that field's baseline. Reports that arrive while the field is not focused never write.
  - A report equal to the baseline writes the original stored string, so typing back to the start restores the original HTML exactly.
  - Undo, Page's Fit and remote updates reload an editor that is not focused.
  - The editor's `<html>` wrapper and newlines are removed, and empty first/last lines are dropped.
- **Improve** (`ai.improve`):
  - It works on the line at the caret: Stronger verb, Add a result, Make it shorter, or "Ask for something else…". Then Replace or Keep mine.
  - Replace swaps only that block's text. If the line changed since Improve was asked, the suggestion is not applied ("The line changed since you asked…").
  - Without a provider it shows `AIProviderSetupSheet` from M6-T4's `useHasAIProvider`.
- **Dates**:
  - Start, End and Present for a range; one Date for awards, certifications and publications.
  - Typed values are read in the resume's locale, as on web ("Mar 2022", "03/2022", "2022-03", "2022", "März 2022").
  - A month picker is available from the calendar button: a spinner in a sheet with Clear/Done on iOS, the system dialog on Android.
  - The notes say when a date is unreadable, when it came from a `raw` text that needs a look, and when the range is reversed. Editing a date clears `raw`. The legacy `period`/`date` text follows on save (M3-T3's `syncResumeDates`).
- **Pickers**:
  - Icon: None, 21 common icons, and search over every resume icon.
  - Colour: web's 16 presets plus a hex/rgba field, per README §1.4 (swatches + hex). The full saturation-square picker in mockup E14 was not built.
- **Draft-store use** follows web's semantics:
  - Field typing uses `coalesceKey` (`${entryId}:${field}`, `basics.${key}`, `basics.customFields.${id}.${key}`, `summary.content`, `picture.${key}`).
  - Adding, moving, deleting, hiding and section settings use `newStep`.
  - Inputs forward `resumeFieldFocus` so deferred remote updates apply on blur.
  - A locked resume rejects edits in the store, and the UI disables the controls.

## Contract: `src/features/write/fields.ts`

Data only. Design and Check (M4) import:

- `ENTRY_FIELDS: Record<CustomSectionType, readonly EntryField[]>`: each entry type's fields, in order.
  - `EntryField = { key, kind, label: MessageDescriptor, more?: true, keyboard?: "phone" }`.
  - `kind` is one of `text | dates | date | link | richText | keywords | level | icon | roles`.
  - Render a label with `i18n._(field.label)`.
- `PRIMARY_FIELD` (an entry is a draft and does not print until this field is filled), `DRAFT_HINTS`, `SECTION_TITLES`, `ADD_LABELS`, and `SECTION_ICONS` (names from the app's icon map).

Pure helpers that M4 can reuse are in `src/features/write/model.ts`. It has no React and no Lingui. It holds the port of web's `model.ts` and `move-item.ts`, plus the outline's flat-list drop logic. `rich-text.ts` and `dates.ts` are also pure.

The harness runs the shipped `rich-text.ts`, `dates.ts` and `model.ts` and the real M3-T3 `createDraftStore`. The native editor's reports and the network adapter are simulated: the editor stand-in drops `<mark>`, `<span>` and `style`, and rewrites `strong`/`em` and list paragraphs, as the native editor does.

1. `fromEnrichedHtml` removes the wrapper and newlines, turns an empty document into "", and drops blank first and last lines.
2. Mounting three editors, then focusing and blurring them without typing, sends no update and no save. Their highlights, alignment and colours survive byte for byte.
3. Editing one description sends a save that re-serialises only that field. The summary and the other description keep their original HTML, and the rest of the resume deep-equals the original.
4. Typing back to the original writes the stored HTML, not the editor's version, and does not write twice.
5. An edit made before the baseline arrives is held, then written. An empty field writes at once.
6. An unfocused editor reloads an undo or remote change without writing. A focused editor ignores the remote change, which M3-T3 defers to blur.
7. Improve: the line at the caret; Replace keeps the block tag and escapes text; a line that changed is not replaced.
8. Dates:
   - Parsing in en-US and de-DE: month name, numeric, ISO and year-only forms.
   - Formatting in short, long, numeric and iso.
   - The picker round trip.
   - Reversed ranges, including a year-only end and Present.
   - Editing clears `raw`.
9. Outline drag: Skills dragged from the Sidebar above Education lands in Page 1's main column after Experience. An entry dragged out of its section snaps to that section's end.
10. Move to…: emptying a custom section removes the section and its now-empty page.

Test-audit gate: these scenarios protect losses that would be silent, mainly rich-text loss in fields the user did not touch, and layout changes on drop. Web tests cannot reach the native editor's gate, so the checks are kept as a manual harness (as in M3-T3). No Vitest suite, test-only export or production seam was added.

Two checks of the harness itself:

- Scenario 9 found a real bug during development. `applySectionDrop` kept a reference to a column array that `removeFromLayout` replaces, so a section dragged across columns vanished from the layout. It is fixed.
- With the focus gate and the baseline substitution removed from `rich-text.ts`, scenario 2 fails. With the code restored, all 10 pass.

## Limits and follow-ups

- **Draft owner per pane:**
  - Write and Page each call `useResumeDraft(id)`, following M3-T4's pattern. The panes switch with `router.replace`, so each switch closes and reopens the draft, which resets undo history.
  - Move the owner hook to `app/builder/[id]/_layout.tsx` (M2-T2/coordinator) once the chrome lands. Then the panes can drop their calls.
  - Entry screens never own the draft; they read the store of the pane beneath them.
- **Chrome:** the panes use plain screen content and the existing stack header. Two things wait for M2-T2's `BuilderChrome`: tablet layout (panel + page, section popover) and the save-status slot.
- **Device checks still owed** (coordinator smoke test, both themes):
  - enriched-html: the initial-load `onChangeHtml` and `getHTML` timing that the baseline relies on.
  - The toolbar above the keyboard, including interactive dismissal on iOS.
  - Drag handles inside `ReorderableList` cells.
  - The iOS spinner date picker in a sheet.
  - Image-picker crop on both platforms.
  - Sheet stacking: Rename and Icon pickers close the section sheet first.
- **Not built:**
  - "Proposed" badges for assistant edits (M6-T3 owns proposals).
  - Mockup E14's saturation/hue picker; swatches + hex per README §1.4.
  - Icon glyph previews for search results: only the 21 suggested icons, which are in the app icon map, show a glyph. Search results show names, because the PDF's Phosphor paths are not exported to the app.
  - A camera source for the resume photo: the library only, because app config has no camera permission string for this use.
- **For M3-T2:** after an import, navigate to `routes.builder(id)` with `?imported=<source label>` to show the Imported banner.
- **Lingui:** new strings use macros. Extraction was not run (coordinator, per wave).
