# M5-T2: Application detail

Status: succeeded. Branch: `mobile/M5-T2`. Base: `mobile/native-app` @ `3cc181206`. Local commit only; no push.

## Delivered

- `app/applications/[id]/[tab].tsx` is a thin dispatcher. A workspace tab id (`fit`, `apply`, `prepare`, `practise`, `debrief`, `messages`, `saved`, from `WORKSPACE_TABS`) renders `src/features/workspace/tabs/<id>.tsx`. Any other value, by convention `details`, renders the application detail from `src/features/application-detail`.
- The seven workspace tab files are placeholders (a `RouteStub` with the translated tab name). M6-T2 owns and fills them. `app/applications/[id]/_layout.tsx` (M2-T2) was not touched.
- The application detail screen (`detail-screen.tsx`, `sections.tsx`, `sheets.tsx`, `interview-sheet.tsx`) follows the mockup frames `app-detail` … `app-follow-up` and the web detail sheet and workspace context column:
  - **Header:** role, company · location, and View posting. The posting sheet shows the link, its provenance, a clipped/incomplete warning, "What it asks for" and an editable job description.
  - **Stage stepper:** Saved → Offer, with the time spent in the current stage and Move to next. Saved → Applied opens Mark as applied: date, resume/letter submitted, and the attached files that were actually sent. The stepper also shows a pending move until the refetch lands.
  - **Closed applications:** an Outcome card (reason · date) and Reopen. Close application… opens a reason sheet.
  - **Next step card:** ported `getNextStep`/`describeNextStep`.
    - The time shows in the user's timezone, plus the interview's own timezone when it differs.
    - Actions: Edit or Schedule an interview, Reminder, Add to calendar (`.ics`), and Set/Change the follow-up.
    - Overdue steps use the warn tone.
  - **Open workspace** opens the tab for the stage (web rule 7).
  - **What you sent:** linked resume and letter, with "Version sent {date} · Check N" or "Linked · not sent yet". Each opens its builder. Without them: Prepare a resume (opens `new?step=copy&applicationId=<id>`, M3-T2's copy-for-job step) and Write a letter (`coverLetters.create` with `applicationId`, then the letter editor).
  - **Facts:** role, company, location, salary, source and posting link edit inline. Done or blur saves; an unchanged value saves nothing; the link must be http(s); role and company can't be emptied. The typed text stays in the field until the save succeeds; a failure shows an inline error for retry. Applied is read-only.
  - **Tags:** `ChipInput`.
  - **Contacts:** a sheet with the list, remove, and add. The email is validated with the API's `contactSchema`. Label chips: Recruiter, Hiring manager, Referral, Interviewer.
  - **Notes:** autosave 800 ms after typing stops, plus on blur and on leaving. Saves go through `notes-queue.ts`: one request per application at a time, and edits made meanwhile coalesce into the next request (latest text wins). Typed text is kept in `expo-sqlite/kv-store` under `reactive-resume:application-notes:<server+account scope>:<id>` until a save of it succeeds, and is restored on the next visit. A failed save keeps the text and shows Retry save.
  - **Timeline:** newest first, with Add a note. A stage or note row opens an edit sheet (day, note text). An interview row opens the interview editor. Delete asks for confirmation, and the entry that anchors the current stage cannot be deleted.
  - **Attachments:** resume and cover-letter PDFs.
    - Pick through `expo-document-picker` (`application/pdf`). The PDF-only, ≤ 10 MB check (`attachment.ts`, mirroring the API's `MAX_APPLICATION_DOCUMENT_BYTES`) runs before upload.
    - Upload is multipart `POST /applications/{id}/documents/{kind}` through `rest()`, the same pattern as M7-T1's avatar upload. The picker's cache copy is deleted afterwards.
    - Tap to preview: the in-app browser opens the stored upload URL (`/uploads/*` is served without auth). Remove asks for confirmation (`applications.removeDocument`).
  - **Delete…:** confirmation, delete, cancel this application's reminders, back to Applications.
- **Interview editor:**
  - Fields: type chips, date and time pickers, and length 30/45/60/90 (keeps a custom stored length). Location, Who you'll meet (name, role, public-HTTPS profile link; at most 20), what they asked you to prepare, and Remind me on this device with a lead time.
  - Date and time are a wall clock in the interview's timezone, converted with `fromZonedDateTime` from `@reactive-resume/utils/timezone`. A skipped DST time is rejected before saving. An unchanged clock time keeps the exact stored instant.
  - "Interview is in another timezone" opens a searchable IANA zone list and the line "07:00 in X is 16:00 in your timezone (Y)".
  - Delete hides the interview at once with an Undo toast and commits after 6 s (web `withUndo` behaviour). Its reminder is held (sync leaves it alone) through the undo window and is cancelled only after the delete succeeds; Undo keeps it.
- **Reminders (`src/features/reminders`):** local `expo-notifications` only, with a DATE trigger and the Android channel `reminders`.
  - Permission is asked only when the user turns a reminder on. If permission is denied: "Notifications are off", Open device settings, and the `.ics` alternative.
  - Interviews: 10 min, 30 min (default), 1 h or 1 day before. Follow-ups fire at 09:00 on the follow-up day, in the user's timezone.
  - Identifiers are `interview:<entryId>` and `follow-up:<applicationId>`, so scheduling again replaces a reminder. The lead time and start are kept in the notification `data`.
  - `syncReminders` runs each time the detail loads a new version of the application. It reschedules moved interviews, including ones moved on the web, and cancels reminders for deleted interviews, cleared follow-ups and closed applications.
- **`.ics` share:** `buildIcs` is ported from web (UTC, RFC 5545 escaping) with folding at 75 UTF-8 octets between code points. `interviewEvent`/`followUpEvent` build the events; like web, an interview's DESCRIPTION is only its notes, never the people. It is written to the cache and shared through `expo-sharing` (`text/calendar`, `com.apple.ical.ics`); no calendar permission is needed. The previous share's `.ics` files are swept before the next one.
- **Timezone:** the user's profile timezone (Settings → Preferences, `auth.getProfile`). Web falls back to UTC; mobile falls back to the device timezone.
- Every user-facing string uses Lingui macros; no extraction was run. Colours come only from tokens. No new dependencies; manifests, lockfile, `queries.ts`/`stages.ts` exports and M1 contracts are unchanged. App identity `me.rxresu` is untouched.

## Contracts

- **Route:** `routes.applicationDetails(id)` → `/applications/<id>/details` (any tab id outside `WORKSPACE_TABS`) shows the detail; the Applications list and the add sheet open it. Workspace tabs stay `/applications/<id>/<WorkspaceTab>` and get a "Details" header button from the dispatcher.
- **Workspace tabs:** `src/features/workspace/tabs/<id>.tsx` each export `<Name>Tab` (`FitTab`, `ApplyTab`, `PrepareTab`, `PractiseTab`, `DebriefTab`, `MessagesTab`, `SavedTab`), currently with no props. They read `id` with `useLocalSearchParams`, or M6-T2 adds props in the dispatcher.
- **`@/features/reminders`** (for M5-T3 calendar and M6-T1 Today):
  - `useReminders(applicationId)` → `{ leadFor(target), turnOn(target, lead): "scheduled" | "denied" | "passed", turnOff(target) }`
  - `syncReminders(applicationId, targets)`, `shareIcs(event, fileName)`, `buildIcs`, `icsFileName`
  - Pure helpers: `reminderTime`, `followUpStart`, `zonedParts`, `REMINDER_LEADS`, `interviewEvent`, `followUpEvent`
  - `holdReminder(entryId)` / `releaseReminder(entryId)` keep `syncReminders` off an interview behind an undo toast
- **`@/features/application-detail/hooks`:** `interviewReminder(application, entry)`, `followUpReminder(application)`, `reminderTargets(application)`, `useUserTime()`, `useDetailMutations(id)`.
- `InterviewSheet` takes `{ application, interview | null, open, onClose }`. M5-T3's calendar can reuse it for an existing application; it has no application picker.

## Review fix round: Codex `b1142334`

Merged `mobile/native-app` first (clean; brings M3-T2). Fixed all 6 blockers:

1. **Notes saves overlap** (`sections.tsx`): new `notes-queue.ts` serializes saves per application; edits during a request coalesce into the next one, latest text wins, so an older response can no longer land after newer text. The save calls the client directly, so it outlives the screen.
2. **Failed notes drafts lost**: typed text is kept in kv-store, keyed by server + OAuth account (`getDraftScope`) + application, until a save of that text succeeds; it is restored on the next visit and retried.
3. **Inline facts dropped drafts**: `InlineFact` awaits `mutateAsync`, clears only on success, and keeps the text with an inline error on failure. Done and blur no longer double-save.
4. **Reminder lost on Undo**: the reminder is held during the undo window and cancelled only after the delete commits; Undo releases the hold and keeps it.
5. **`.ics` exported people**: `interviewEvent` puts only the interview notes in DESCRIPTION, as web.
6. **Folding**: by UTF-8 octet length at code-point boundaries (≤ 75 octets per line, continuation space included).

Coordinator-approved navigation extension: `routes.applicationDetails(id)` in `src/routes.ts`; `list-screen.tsx` and `add-sheet.tsx` open it; the `[tab].tsx` dispatcher adds a "Details" header button on workspace tabs (`router.replace`). "Prepare a resume" now preselects the application through M3-T2's `new?step=copy&applicationId=`.

New scenarios: UTF-8 folding with CJK/emoji (each line ≤ 75 octets, no split surrogates, unfolds to the original; the pre-fix code produced 103-octet lines), interview DESCRIPTION without people, notes saves coalescing with one request in flight, and failed-save retention and retry.
