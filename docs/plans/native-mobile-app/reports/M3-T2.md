- Library: title/tag/linked-company/linked-role search, All/Resumes/Letters counts, intersecting tag filters, public-only filter, edited/name/created sorting, phone list default, tablet grid default, grid/list toggle, pull-to-refresh, loading skeletons, empty/no-match/retry states, and Trash as the final library row. - Selection starts through Select, the card menu or a long press with light haptics. Typed document keys distinguish resumes and letters. Bulk tags apply shared-tag additions/removals while retaining unique tags. Bulk visibility skips letters and locked resumes; locking/unlocking supports both types. Partial failures remain visible and do not close the action sheet as if everything succeeded.
- Card menu: Open, Select, Rename, Duplicate, Copy for a job for resumes, Link to application/Unlink, Tags, Sharing for resumes, Lock/Unlock and undoable Trash. Locked documents disable editing/trash actions. Sharing opens the existing typed Share route; bulk sharing directly changes resume visibility. iOS list swipe actions offer Duplicate and Trash, mirrored for RTL; Android uses the menu.
- Trash: remaining retention days, restore, confirmed permanent deletion, and confirmed Empty Trash. An empty operation is not offered. Partial permanent deletion retains only failed targets for retry. Trash undo restores only successfully moved documents, and waits for a subsequent running action rather than dropping the user's Undo press.
- Small feature-local `Thumbnail` shows a resume placeholder with exactly one `PREVIEW SEAM (M3-T4)` comment. Letter thumbnails use current server body text and the active M3-T3 letter draft when present; they do not open/close the draft owner. No new preview engine or rasterizer was added.
- Cosmetic New badges persist only the latest 50 origin/type/ID keys; opening removes the badge. Storage failures cannot turn a successful duplicate/import into a failed operation. No document contents or credentials are stored by this feature.
- New uses the native route's form-sheet presentation and the M1 primitives. Supports blank and sample resumes, a letter borrowing details/design from the latest edited resume, and named copies optionally linked to an open application. Double submissions are blocked. Import success keeps its created ID even when fetching the optional summary fails, so retry cannot silently make a second import.
- System document picker copies the chosen file into cache. Non-AI imports send an Expo `File` in multipart `file`/`format` fields through `rest("/resumes/file-imports")`: current/v4 Reactive Resume JSON, JSON Resume, LinkedIn ZIP and PDF text. JSON formats are detected by content; account-export resume wrappers are unwrapped. Exported cover letters are schema-validated and imported through `coverLetters.import`.
- Word uses `ai.parseDocx`; PDF has an explicit AI option using `ai.parsePdf`, otherwise it uses server text extraction. Both consume `useHasAIProvider`; missing providers offer `AIProviderSetupSheet` without leaving the import. Actual and reported sizes are checked against 10 MB before encoding/upload, legacy Word is rejected, HTTP/RPC failures have translated recovery text, and server changes between AI parsing and resume creation stop the second write. Requests carry AbortSignals; owned picker-cache copies are removed after success, replacement or unmount.
- Every UI string goes through Lingui; no extraction was run. Colours/type/spacing/radii use Desk & Paper tokens and M1 props. M2's dev folder does not exist on this base, so the existing Forme check remains behind `__DEV__` inside the Documents screen's footer, as authorized.
