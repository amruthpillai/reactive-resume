---
title: "Using Custom Styles"
description: "Convert existing Custom Styles and use Semantic CSS to make targeted, portable changes to your resume PDF."
---

Custom Styles use Reactive Resume Semantic CSS (RRSS), a safe CSS-like language for resume PDFs. Use it after the
regular **Design**, **Typography**, **Layout**, **Page**, and **Picture** settings when you need a targeted override.

<Note>
  RRSS styles the PDF output. It is not browser CSS and cannot load fonts, images, scripts, or other network resources.
</Note>

## Convert existing Custom Styles

When you open a resume that still uses the previous Custom Styles form, Reactive Resume creates a converted stylesheet
draft. Your current rules remain active while you review it.

<Steps>
  <Step title="Open Custom Styles">
    Open the resume in the builder, select **Design**, then select **Custom Styles**.
  </Step>
  <Step title="Review the converted draft">
    Check the preview and any warnings below the editor. The draft starts with `@rr-version 1;`.
  </Step>
  <Step title="Activate Semantic CSS">
    Select **Activate Semantic CSS** only after the preview matches the legacy result. Activation never applies both
    systems at once, and the original legacy rules remain available for rollback.
  </Step>
</Steps>

## Add a targeted rule

RRSS selectors describe the resume instead of a template's internal layout. This rule changes every Experience section
heading:

```css
@rr-version 1;

section[type="experience"] > section-heading {
	text-transform: uppercase;
}
```

To target one section, use its stable ID:

```css
section[id="projects"] {
	padding: 6pt;
	break-inside: avoid;
}
```

Use exact item IDs only for resume-specific adjustments. Prefer section types, roles, fields, and placements when you
want to copy the stylesheet to another resume.

## Use builder colors and dimensions

Read-only `--rr-*` variables expose the resume's current visual settings:

```css
:root {
	--accent: var(--rr-primary-color);
}

header > name,
section-heading {
	color: var(--accent);
}
```

Changing the primary color in the builder updates this stylesheet automatically. RRSS does not expose font-family or
asset variables.

## Style rich text and template parts

Rich-text elements use semantic names:

```css
rich-text list-item > list-item-content {
	line-height: 1.25;
}
```

Template-specific details are exposed only when the selected template publishes that part:

```css
resume[template="azurill"] template-part[name="timeline-dot"] {
	background-color: var(--rr-primary-color);
}
```

Keep template-part rules behind a template selector. Portable rules should target shared semantic elements.

## Check and recover from errors

The status below the editor shows compile and PDF-render diagnostics with line and column numbers. Invalid source is
saved so you do not lose work, while the preview and PDF export continue using the last valid applied stylesheet.

Fix the reported error and wait for **Applied** before comparing or exporting the updated PDF. Use **Reset to applied
stylesheet** to discard the current draft, or the stylesheet undo and redo buttons to restore an earlier source/applied
pair.

## Work in compact or focus mode

The editor starts in a compact panel. Select **Open focus mode** for a taller editor while keeping the preview visible
on desktop. On mobile, the same action opens an accessible full-width sheet; switch to **Preview** to inspect the result.

## Copy styles between resumes

1. Select **Copy stylesheet** in the source resume.
2. Open **Custom Styles** in the destination resume.
3. Paste the stylesheet.
4. Review warnings for exact IDs or template parts that are absent.
5. Wait for **Applied**, then compare the preview and exported PDF.

Rules based on semantic types, roles, fields, and placements are portable. Exact section/item IDs and template-part
rules are intentionally resume- or template-specific.

See [Semantic CSS Reference](/guides/semantic-css-reference) for all elements, attributes, properties, units, variables,
and template-part names.
