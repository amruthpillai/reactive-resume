Reactive Resume Semantic CSS (RRSS) is the versioned stylesheet language for styling resume PDFs. It resembles CSS,
but supports only the semantic selectors, values, properties, and PDF behavior documented on this page.

## RRSS in one minute

Start every authored stylesheet with `@rr-version 1;`. Version 1 is immutable: a missing directive is accepted with a
warning and interpreted as version 1, while unsupported versions are rejected.

RRSS selectors target the semantic resume tree rather than template markup. Prefer section types, placements, roles,
and semantic element names for portable styles. Use IDs when a rule should target one node in one resume.

<!-- RRSS-EXAMPLE:valid -->
```css
@rr-version 1;

:root {
	--accent: #2563eb;
}

section-heading {
	color: var(--accent);
	border-bottom: 1pt solid var(--accent);
	padding-bottom: 3pt;
}

section[type="experience"] > section-items > item + item {
	margin-top: 8pt;
}

region[placement="sidebar"] section-heading {
	font-size: 10pt;
	text-transform: uppercase;
}
```

## Selector grammar

RRSS supports the universal selector, semantic type selectors, IDs, attributes, selector lists, and the descendant
(` `), child (`>`), adjacent-sibling (`+`), and general-sibling (`~`) combinators.

<!-- RRSS-EXAMPLE:valid -->
```css
* { opacity: 1; }
section { margin-bottom: 8pt; }
#experience { break-before: page; }
[role~="primary-text"] { font-weight: 700; }
section[type="experience"] > section-items > item:first-child { margin-top: 0; }
field[name="company"], field[name="position"] { color: #111827; }
section:is([type="experience"], [type="education"]) { break-inside: avoid; }
item:not(:last-child) { margin-bottom: 6pt; }
```

Attribute selectors support presence selectors such as `[type]` and all six value matchers: `=`, `~=`, `|=`, `^=`,
`$=`, and `*=`. Attribute names and values are ASCII case-sensitive: `[type="experience"]` can match, while
`[TYPE="experience"]` is invalid and `[type="Experience"]` does not match the lowercase runtime value. Attribute
selector flags, custom classes, and pseudo-elements are rejected.

RRSS accepts digit-leading ID selectors such as `#229ad766-cb9a-4f16-aaf0-fdd8394a9b95`. Standard CSS escaping is
also supported for type, attribute, and ID names; a hexadecimal escape ends with whitespace when the following
character could be read as another hexadecimal digit. For portability across CSS tools and unambiguous authoring,
prefer quoted `[id="…"]` selectors for UUID-bearing IDs.

<!-- RRSS-EXAMPLE:valid SELECTOR_ESCAPING -->
```css
@rr-version 1;

[type] {
	opacity: 1;
}

[id="229ad766-cb9a-4f16-aaf0-fdd8394a9b95"] {
	break-inside: avoid;
}

sect\69 on[\74 ype="experience"] > section-heading {
	color: #2563eb;
}

#\31 abc {
	break-before: page;
}
```

Supported pseudo-classes and restrictions:

- `:root`, `:first-child`, `:last-child`, and `:only-child` take no arguments.
- `:is()`, `:where()`, and `:not()` require a selector list.
- `:nth-child()` and `:nth-of-type()` accept integer `An+B`, `odd`, and `even`.
- `:nth-child()` may use an `of <selector-list>` clause.
- `:nth-of-type()` does not accept an `of` clause.
- A compound selector may contain only one semantic type selector.
- Selector functions, selector lists, selector length, and combinators are bounded by the generated limits.

Media queries use comma-separated OR branches and `and`-combined features. Supported features are `width`,
`min-width`, `max-width`, `height`, `min-height`, `max-height`, and `orientation: portrait|landscape`. Dimensions
accept finite numbers with `pt`, `px`, `in`, `mm`, `cm`, `vw`, `vh`, `em`, or `rem`; omitted units resolve as points.
Media rules evaluate against authored PDF dimensions, may nest up to the generated limit, and cannot contain `size`.

## Cascade and values

The cascade resolves declarations in this order:

1. `!important` wins first.
2. Higher specificity wins next.
3. Later source order breaks the remaining tie.

For a selector list, RRSS uses the highest-specificity branch that actually matches the node. `:where()` contributes
zero specificity; `:is()` and `:not()` use their most specific nested selector.

CSS-wide keywords resolve against the semantic tree and the template/builder base:

- `inherit` reads the semantic parent's resolved value.
- `initial` removes the authored value.
- `unset` inherits inherited properties and removes non-inherited properties.
- `revert` restores the template/builder base value.

Author custom properties inherit through the semantic tree, and `var()` supports nested fallbacks. A missing variable
without a fallback and a variable cycle are errors. Names beginning with `--rr-` are read-only runtime values; author
variables must use another prefix.

Units resolve against PDF points, authored page dimensions, the root font size, or the current or parent font size as
appropriate.

## Property reference

The generated table is the complete version-1 property catalog. `Applies to` identifies the semantic nodes accepted by
each property. Known keywords are completion hints rather than the full value grammar; property-specific parsers also
accept the documented numbers, colors, functions, and shorthands.

### Value grammar

RRSS value families are:

- **CSS-wide keywords:** `inherit`, `initial`, `unset`, and `revert` must be the complete property value. They cannot be
  mixed into a multi-token shorthand.
- **Variables:** `var(--name)` and nested fallbacks such as `var(--name, var(--fallback, #2563eb))` are supported.
  General CSS math functions such as `calc()`, `min()`, `max()`, and `clamp()` are not part of version 1.
- **Numbers:** `opacity` accepts a finite number from `0` to `1`; `flex-grow` and `flex-shrink` accept finite numbers.
  `order`, `orphans`, `widows`, `z-index`, and `max-lines` accept integers. `orphans` and `widows` must be at least `1`.
- **Lengths:** a finite number followed by `pt`, `px`, `in`, `mm`, `cm`, `%`, `vw`, `vh`, `em`, or `rem`. An omitted
  unit means points. `line-height` also accepts a unitless multiplier or `normal`.
- **Colors:** CSS named colors, `transparent`, hexadecimal colors, `rgb()`, `rgba()`, `hsl()`, and `hsla()`.
- **Booleans:** `-rr-fixed` accepts `true`, `false`, `1`, or `0`.

Flex alignment accepts the PDF renderer's fixed keyword sets:

- `align-content`: `flex-start`, `flex-end`, `center`, `stretch`, `space-between`, `space-around`, or `space-evenly`;
- `align-items`: `flex-start`, `flex-end`, `center`, `stretch`, or `baseline`;
- `align-self`: `auto`, `flex-start`, `flex-end`, `center`, `stretch`, or `baseline`;
- `justify-content`: `flex-start`, `flex-end`, `center`, `space-between`, `space-around`, or `space-evenly`;
- `flex-direction`: `row`, `row-reverse`, `column`, or `column-reverse`; and
- `flex-wrap`: `nowrap`, `wrap`, or `wrap-reverse`.

`flex` accepts `none`, `auto`, one basis value, one grow number, `grow basis`, or `grow shrink basis`. `flex-flow`
accepts one direction, one wrap mode, or one of each.

<!-- RRSS-EXAMPLE:valid FLEX_VALUES -->
```css
@rr-version 1;

section-items {
	display: flex;
	flex-flow: column nowrap;
	align-items: stretch;
	gap: 8pt;
}

item {
	flex: 1 1 0%;
	align-self: stretch;
}

item-header {
	display: flex;
	flex-direction: row;
	justify-content: space-between;
}
```

For pictures, `object-fit` accepts `contain`, `cover`, `fill`, `none`, or `scale-down`. `object-position` accepts one or
two horizontal/vertical keywords (`left`, `right`, `top`, `bottom`, or `center`), percentages, or lengths.

<!-- RRSS-EXAMPLE:valid IMAGE_VALUES -->
```css
@rr-version 1;

picture {
	width: 96pt;
	height: 96pt;
	aspect-ratio: 1;
	object-fit: cover;
	object-position: center 25%;
	border-radius: 48pt;
	-rr-shadow-color: rgba(15, 23, 42, 0.2);
	-rr-shadow-width: 3pt;
}
```

`transform` accepts `translate()`, `translateX()`, `translateY()`, `rotate()`, `scale()`, `scaleX()`, `scaleY()`,
`skew()`, `skewX()`, `skewY()`, and six-number `matrix()`. Rotation and skew angles accept degrees or radians.
`transform-origin` accepts one or two position keywords, percentages, or lengths.

<!-- RRSS-EXAMPLE:valid TRANSFORM_VALUES -->
```css
@rr-version 1;

picture {
	transform: translateX(3) rotate(4deg) scale(1.02);
	transform-origin: center center;
}
```

Color functions and `var()` may be combined, including nested fallbacks. `url()` and resource-loading functions remain
forbidden.

<!-- RRSS-EXAMPLE:valid COLOR_FUNCTIONS -->
```css
@rr-version 1;

:root {
	--accent: hsl(217, 91%, 60%);
	--surface: rgba(37, 99, 235, 0.08);
	--border: rgb(203, 213, 225);
}

name {
	color: var(--accent, #2563eb);
}

section {
	background-color: var(--surface);
	border-color: var(--border);
}

field[role~="secondary-text"] {
	color: navy;
}
```

`margin`, `padding`, `border-width`, `border-style`, `border-color`, and `border-radius` accept one to four values using
CSS top/right/bottom/left expansion. `gap` accepts one or two lengths. `border` and per-side border shorthands accept
width, style, and color in any order; use the renderer-supported `solid`, `dashed`, or `dotted` border styles.
Slash-separated elliptical border radii are not supported.

<!-- RRSS-EXAMPLE:valid SHORTHANDS -->
```css
@rr-version 1;

section {
	margin: 6pt 0 10pt;
	padding: 8pt 12pt;
	border: 1pt solid #cbd5e1;
	border-radius: 6pt;
}

section-items {
	gap: 6pt 10pt;
	flex-flow: column nowrap;
}
```

Common constrained text values are:

- `font-style`: `normal`, `italic`, or `oblique`;
- `font-weight`: a numeric weight or `thin`, `hairline`, `ultralight`, `extralight`, `light`, `normal`, `medium`,
  `semibold`, `demibold`, `bold`, `ultrabold`, `extrabold`, `heavy`, or `black`;
- `text-align`: `left`, `right`, `center`, or `justify`;
- `text-decoration`: `none`, `underline`, `line-through`, or both line values;
- `text-transform`: `none`, `capitalize`, `lowercase`, `uppercase`, or `upperfirst`;
- `text-overflow`: `ellipsis`; and
- `vertical-align`: `sub` or `super`.

<!-- RRSS-EXAMPLE:valid PROPERTY_VALUES -->
```css
@rr-version 1;

field {
	font-size: 10pt;
	font-style: italic;
	font-weight: 600;
	line-height: 1.35;
	text-align: left;
	text-decoration: underline;
	text-transform: uppercase;
	opacity: 0.85;
}
```

## PDF behavior

RRSS applies styles to existing semantic PDF nodes:

- `display: none` hides an existing semantic node; RRSS never deletes source data.
- `order` changes stable sibling render order, with original semantic order as the tie-breaker.
- `break-before`, `break-inside`, `-rr-min-presence-ahead`, `orphans`, `widows`, and `-rr-fixed` map to bounded React
  PDF behavior.
- `size` applies only to `page` outside `@media`; one or two lengths create a custom page size.
- RRSS cannot create, re-parent, or duplicate arbitrary nodes. Fixed content repeats only an existing semantic node.

Invalid editable source remains saved, while preview and export keep the last source that compiled and passed PDF
preflight.

## Unsupported capabilities and portability checklist

Before sharing a stylesheet across resumes or templates, check that it:

- starts with `@rr-version 1;`;
- targets semantic types, attributes, roles, or stable IDs rather than template implementation details;
- guards every template part with `resume[template="..."]`;
- uses only properties and values in the generated reference;
- stays within the generated compiler and PDF preflight limits; and
- does not depend on creating or loading content.

The following capabilities are unsupported:

- class selectors and pseudo-elements;
- CSS Grid;
- `@import`, `@font-face`, `@supports`, and arbitrary at-rules;
- `url()`, external or local assets, and font loading;
- scripts and browser layout APIs;
- interaction states, animations, and transitions;
- filters and gradients;
- general `box-shadow` and `text-shadow`; and
- node creation, arbitrary duplication, and re-parenting.

Picture shadows are available only through `-rr-shadow-color` and `-rr-shadow-width`.

<!-- RRSS-EXAMPLE:invalid INVALID_SELECTOR -->
```css
@rr-version 1;

section::before {
	content: "Unsupported";
}
```

Pseudo-elements are rejected because RRSS cannot create PDF nodes.
